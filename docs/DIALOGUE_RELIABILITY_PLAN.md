# 对话可靠性与角色连续性改造方案

日期：2026-09-28。状态：工程修复已实施并复验；两档 Hosted 各两组共 24 轮的更正/遗忘定向复测通过，完整模型质量评估和平台放行尚未全部完成。实施证据见 [修复报告](qa/dialogue-repair/FINAL-REPORT.md) 和 [续接交接](qa/dialogue-repair/RESUME.md)。依据是当前月栖真实模型评估、用户提供的 Float 本地源码，以及公开的一手文档。本方案不代表已达到发布门槛。

## 1. 产品目标：有内在因果的角色

“真实的心理活动”在产品中应指：性格、已知经历、当前心绪与当下反应之间有可理解的联系，反应能影响后面的表达，而且跨轮连续。它可以含犹豫、不满、偏心、害羞、矛盾和误会，不必永远温柔、正向或迎合用户。

这能做成可信的角色模拟，但不能证明模型有主观体验，也不能把供应商原始推理直接标成角色真实内心。提供商推理控制的是生成计算；角色心绪是产品里的叙事状态，两者分开。

对于虚构人物，作者设定的身体、职业、房间和日常可以在角色世界中成立。平台不应把所有导入人物都改写为“没有身体、不能喝咖啡”的同一种数字人格。要明确的是：**角色世界成立的事、用户现实生活中的事、产品实际完成的操作，是不同的事实域。** 作者设定可以包含青梅竹马等虚构既往关系，但不能据此断言真实账号过去发过某条消息或发生过一次现实交易。

## 3. 心理活动：状态与表达相连

沿现有 `inner-state`、runtime 和角色/会话状态演进，不增加一套每轮循环调用工具的“心理 Agent”。

1. **生成前有依据。** 本轮读取人格、可信回忆、当前情境及上一轮已确认的角色状态。状态可以描述当前在意的小事、没说出口的感受、尚未解决的关系话题，而非统一的亲密度分数。
2. **区分感受和事实。** “我有点担心是不是说重了”是角色自己的感受；“用户生气了”只能是可撤回的判断，不能存成用户事实。猜测保留角色主观性与不确定性；用户澄清后，旧理解能失效。
3. **同一轮表达一致。** 默认一次回复调用根据同一份状态产生说出口的话与可选内心，并提交小型状态变化。避免每轮先额外请求长篇心理分析而延迟正文，也避免答完后另编一段完全不影响行为的内心装饰。
4. **只在可靠结束后承接状态。** 验证 runtime/schema、角色/分支、来源与完成状态后提交。失败、取消、未选中的重生成候选不能永久改变角色状态。状态记录关联 assistant candidate / turn ID，便于回切、删除与重建。
5. **心理独白不会变成事实来源。** 不把 raw inner text 送去稳定事实提取，也不每轮累积整段独白。延续的是少量有效状态与关联证据。内心可以省略、可以和表面语气有张力，但要符合人物与实际情境。
6. **显示和计算解耦。** 用户可选关闭、自然出现、更多展示；隐藏显示不应清空角色连续性。默认不强制每轮心理独白。界面可称“心绪/心里话”，避免与供应商推理进度混在同一栏；普通聊天里不展示来源 ID 或置信度。

例：用户说“今天很累，先别给建议”。一个嘴硬但细心的角色可以心里想“差点又多嘴了，先陪着吧”，说出口“行，你说，我听着”。之后不再连续给整理建议；如果用户主动求助，再自然改变回应方式。这里的“真实感”同时体现在内心、口头回答和下一轮行为，而非一句内心文案好听。

若角色需要独立生活，利用已有时间线与作者世界设定，记录明确的 `simulation/shared_fiction` 事件。事件要有角色、发生时间、世界范围和参与者；不能擅自把用户加成参与者，也不能冒充已经操作产品书架、麦克风或日历。此能力单独验证，不以修复为由打开所有默认关闭的实验开关。

## 4. Prompt：统一预算，保护身份，保留编辑自由

现有入口仍为 `compilePrompt → context broker → assemble → finalizeModelRequest`。减少重复分配和相互覆盖，最终只有一份可检查的请求编译结果。

- **预算先保留必要内容。** 修 profile 重标准化；先计算核心人格、当前消息、必要协议、输出预留，再选择近期连续历史、已确认事实和相关世界设定。保护预算与用户设置的发送顺序是两回事，不收回已暴露的排序/深度/启停功能。
- **人格不能静默裁成标题。** 内置人格提供经过对照验证的紧凑核心；作者完整文本仍可查看和编辑。自定义长人格若要压缩，保留完整原文和可编辑的版本化派生内容，预览说明实际发送什么。预算实在不足时给出明确调整方式，不能自动退回通用陪伴人设。
- **历史保持因果。** 优先连续的最近轮次，超长轮次采用有来源的压缩/附件策略；省略清单按真实 message/candidate IDs 记录，不能再用条数猜摘要范围。用户当前消息只进入一次。
- **世界书按条目参与。** 核心世界规则与条件触发条目分配不同预算；沿现有 worldbook matcher，支持已实现的角色/场景范围、启停、顺序与深度。未命中可不插入，不因“新用户没有回忆”就随机填设定。
- **预览即实际请求。** 调试页消费发送时的编译产物，不另拼一份近似 Prompt。可检查每块为什么进入/省略、来源、版本和 tokens；普通聊天不出现这些工程解释。
- **缩减重复平台文案。** 人格负责声音和关系态度；平台文案不再替所有角色规定同一种语气或身体观。作者可选规则维持可选；鉴权、计费、工具权限在代码边界保证，不靠堆进角色对话的文字保证。

原生模型窗口、产品配置的输入预算、回复预算与 reasoning 用量分别记录。不能只改“8000”为更大的数来掩盖预算算法或成本问题。

## 5. 记忆：可追溯、可更正、可失效

继续使用 Conversation V2 作为对话权威、现有稳定记忆/候选账本与 manager 作为治理入口，Context Graph/Palace/向量索引作为可重建的派生视图。先修默认 legacy 正在走的路径，不增加第三套互不一致的事实库。

每条可用事实至少明确：所属用户/角色/关系/现实域，事实内容，证据消息与作者，有效时间，状态与版本；派生项记录来源事实 ID 和版本。事实槽位包含限定条件，例如“咖啡—饮用—晚上—否”，不能只用“不喜欢”的子串判断冲突。

| 信息 | 用途 | 能否自动当作用户事实 |
|---|---|---|
| 用户明确陈述、人工确认 | 当前事实/偏好，附来源 | 可以，但仍处理时间与更正 |
| 用户问题、假设、引用别人的话 | 对话语境或待确认候选 | 不可以 |
| 作者角色背景、已约定虚构关系 | 相应角色世界的 canon | 不可混成账号现实经历 |
| 有记录的角色世界活动 | 虚构世界内连续生活 | 不可声称用户参与或产品工具已执行 |
| 助手问题、心理活动、猜测 | 角色表达或主观理解 | 不可以 |
| 成功工具回执 | 产品真实操作结果 | 可记录结果，不能扩大回执所证明的范围 |

写入流程应是“抽取候选 → 校验证据/类型 → ADD/UPDATE/SUPERSEDE/IGNORE → 幂等提交 → 更新投影”。明确用户事实可以走快速路径，但快速路径也必须识别问句、假设与转述；不能把包含“我喜欢”的文本一律晋升。后台模型提取只处理尚未覆盖的证据，避免前置/后置重复写；不再根据助手回了几个字决定用户事实能否保存。

**更正**必须给旧事实明确的失效/替代关系；图谱、索引、摘要与缓存查询都先检查当前版本。带旧版本的异步摘要晚到时拒绝写回，避免旧信息复活。**忘记**经同一入口作用于所有召回源，并持久化抑制记录。重建索引、刷新、导入和旧任务回调也必须尊重抑制。

还要处理聊天原文：仅删记忆索引不等于模型看不到旧话。用户要求不再用于对话时，Prompt 历史投影与派生摘要应按被忘事实/来源排除或遮盖相关内容；界面保留的原始历史与用于生成的上下文分开。完整删除另走明确的数据删除入口，不能一边保留原文、一边宣称物理永久抹除。混合多项事实的消息按证据范围处理，避免顺手忘掉无关信息。

摘要记录实际覆盖的 message/candidate IDs、各条事实证据与版本。旧摘要不是独立真相源；每次增量更新需要校验来源，删除/更正/重生成会使相关片段失效。无来源的旧摘要先标记待重建，不直接升级为高可信事实。

召回先过滤角色/现实域/失效状态，再组合关键词、时间与语义相关性，去重后按预算选取；没有 embedding 的手工记忆仍可关键词命中。未解决话题、近期更正、约定与用户明确置顶信息优先；不把“最近20条稳定记忆”当成始终相关，也不把相似度当成事实可信度。

## 6. 流式与速度：完成后才能算成功

修复消息队列误清、增量 think 隔离、流内错误/提前 EOF、取消与正文超时。提交顺序收紧为：可靠终止 → 正文/协议验证 → V2 候选提交 → 完成事件与后续记忆。重生成成功前保留旧答，成功后切换候选并失效相关旧派生证据。

详细实现切片及组合边界见 [对话发布门禁](qa/dialogue-evaluation/dialogue-release-gates.md)。复用现有回合快照、V2 候选、证据生命周期、progress event，不另建平行聊天状态机。

Hosted 网关应支持按用途、模型能力验证后的 thinking 策略。先测试日常陪聊关闭/低推理，复杂任务另配；不将这个开关映射为“有没有感情”。每轮不强制多次模型抽取，摘要按新增覆盖与预算压力增量触发，离开前台后可补做并防过期提交。供应商不支持某参数时明确记录能力与回退，不能误报该策略生效。

## 7. 落地顺序与验收

| 批次 | 交付物 | 放行条件 |
|---|---|---|
| A：止住确定性缺陷 | 人格预算/profile修复、正确历史边界；流式隔离/队列/可靠终态；不再补“嗯”装成功 | 已复现 P1 变为回归断言；身份不静默消失；每条已接收输入有归属；失败不写成完整回复 |
| B：统一记忆治理 | 更正/遗忘/幂等、证据类型、摘要版本、迁移与重建 | 检查数据库、最终请求、真实回答三层；旧副本不能在刷新/重建/晚到回调后复活；跨角色与事实域隔离 |
| C：角色连续性与表达 | 角色状态因果、可选内心、人物各自的说话方式、思考策略 | 同一角色跨轮一致；心理误会可澄清；没有机械每轮独白；有性格但不伪造用户经历 |
| D：用户控制与对照评估 | 现有编辑/阅读页接通生效状态、来源、纠正与版本；固定样本盲评 | 用户能发现并改正错误；布局不堆工程字段；真实模型多次采样，相比基线提高且严重事实错误不被平均分掩盖 |
| E：平台放行 | Hosted/BYOK、双壳、Android真机、故障恢复和回滚证据 | 平台分别过门禁；Node/browser通过不能替代真机；保留当前 cutover 限制直至证据齐全 |

工程与模型验收分开。以下是**拟采用的本项目初始目标，不是行业统一标准，也不是已达到的结果**：

- 确定性数据/协议门禁：已定义用例全部通过；零跨角色泄漏、零被遗忘项重新注入、零完整成功状态对应半答、零已接受输入静默丢弃。覆盖所有支持的预算档、长历史、重生成/编辑/删除、随机分块及写入失败。
- 检索与来源：建立人工标注的关键事实/更正集，记录 Recall@K、无来源事实率、纠正命中率、过期事实返回率；先以关键事实召回 ≥95% 作为调优目标，严重来源违规不接受平均分抵消。
- 多轮质量：至少覆盖初次见面、10/30/100轮历史、隔会话、纠正、忘记、反问/假设、换角色、角色世界、情绪转折与边界请求。两档模型固定版本/Prompt，核心场景重复采样。内向、活泼、克制等人物分别测，不把“都温柔”当人格一致。
- 自然度：匿名展示改前/改后样本，人工分别评价接话、节奏、人格、内心一致性、独立性和虚构前情；保存失败样本和评审分歧，模型评分只做辅助。
- 速度：日常短文本正常网络先以首段可读正文 p50 ≤4 秒、p95 ≤10 秒为目标，按具体模型与平台实测；复杂生成另列。进度动画不计作首正文，不以隐藏等待或假打字达标。
- 发布与回滚：记录代码/Prompt/模型/配置指纹；数据迁移可重复、可恢复，先影子对比新旧召回再切换。旧原文不因迁移被销毁，缓存可从权威重建；不以“兼容”为由把已忘记的旧索引重新读回来。

生产日志默认只留耗时、终态、块预算和必要指纹；调试导出才由用户明确选择内容范围。原始供应商推理不收集，密钥不落客户端包或报告。用户侧看到自然的聊天与清楚的错误恢复；诊断细节留在可打开的工具页。

## 8. 本轮结论与状态

已完成故障基线及人格预算、记忆证据/更正/遗忘、流式终态、角色心绪和双壳维护的工程修复。详细证据与剩余质量/平台门禁见上述修复报告。真实请求完成数不等于语义质量通过数；人工盲评、完整多轮重复采样、Android 与 Live BYOK 仍需独立证据。“产业级”以可验证的行为和恢复能力为目标，不以新模块数量、一次演示或“零 bug”承诺命名。
