# AIPlatform 语义纠正方案

目标：保留 AIPlatform 的“类手机桌面”外壳，但把第一层产品语义从“AI 工具桌面 / 后台配置台”纠正为“人机恋陪伴系统”。它和 Yueqi Companion 的核心能力不应相差很多，只是表达方式从轻量 App 主界面变成手机桌面容器。

## 一、当前实现错误

1. 桌面第一屏暴露了后台词：`API设置`、`数据管理`、`商城`、`美化`。
   用户进入后感受到的是工具箱，而不是一个陪伴对象和关系空间。

2. `MemoryManagerApp` 现在是同步队列和开发调试页。
   这不该作为用户入口出现。用户需要看到的是“日记 / 回忆 / 收藏馆”，底层的记忆写入、RAG、同步队列应藏到系统层。

3. `世界书`和`个人资料`的关系不清楚。
   世界书不是普通笔记，也不是技术配置。它应该和角色、人设、关系边界、世界观绑定，是“角色与世界”的编辑页。

4. `音乐 / 相册 / 小说 / 日历`现在像孤立 App。
   它们应是生活资料入口：音乐用于陪伴氛围和同步听歌，相册用于关系照片和场景，日历用于纪念日/约定/主动消息节奏，阅读用于共同文本和世界材料。

5. 桌面 Widget 仍然是通用 OS 语义。
   倒计时、存储、电量等可以保留为视觉元素，但首页 Widget 应优先显示陪伴状态：在一起天数、今日天气、AI 作息、情绪、最近日记、下一次约定。

## 二、正确的信息架构

### 桌面 Dock

Dock 只放最高频、低理解成本入口：

- `聊天`：主入口，类似短信/微信。所有关系发生从这里开始。
- `日记`：每日关系沉淀。用户看到的是日记列表和收藏馆，不看到数据库和检索细节。
- `世界`：角色 + 世界书 + 关系设定的入口。
- `生活`：音乐、相册、日历、位置、阅读等生活场景入口。

### 桌面主屏

主屏建议三页：

1. `今日`
   - 角色状态 Widget：online / 睡眠 / 被吵醒 / 情绪。
   - 天气与位置 Widget：只展示用户环境，不解释 MCP。
   - 在一起天数、消息总数、日记总数。
   - 最近日记一行预览。

2. `陪伴`
   - 聊天
   - 日记
   - 世界
   - 音乐
   - 相册
   - 日历
   - 一起读
   - 我的

3. `系统`
   - 接口
   - 同步与备份
   - 权限
   - 外观
   - 更新
   - 开发日志

系统页可以存在，但不能和陪伴页混在一起。

## 三、模块命名映射

| 当前名称 | 应改为 | 产品语义 |
| --- | --- | --- |
| API设置 | 接口 / 高级接口 | 只在系统页出现，用于模型供应商和云同步 |
| 数据管理 | 同步与备份 / 开发队列 | 不作为用户日常入口 |
| MemoryManager | 日记 / 回忆 | 用户只看到日记、收藏馆、历史日期 |
| 世界书 | 世界 | 包含角色、人设、世界书、边界和关系规则 |
| 个人资料 | 我的 / 用户画像 | 用户资料与偏好，不等于角色设定 |
| 小说 | 一起读 | 可作为世界材料和共同阅读场景 |
| 美化 | 外观 | 系统页设置，不放陪伴主屏 |
| 商城 | 暂时移除 | 没有真实生态前不要占入口 |

## 四、文件级纠正点

需要调整：

- `openApp()` 增加语义别名：
  - `聊天`、`Pop`、`Message` -> `AppView.WECHAT`
  - `日记`、`回忆` -> `AppView.MEMORY`
  - `世界`、`世界书` -> `NOTES`
  - `音乐` -> `AppView.MUSIC`
  - `相册` -> `AppView.PHOTOS`
  - `接口`、`系统`、`设置` -> `AppView.SETTINGS`

- `dockApps` 从通用手机四件套改为：
  - `聊天` / `MessageCircle`
  - `日记` / `BookOpen`
  - `世界` / `FileText`
  - `生活` / `Sparkles` 或 `Grid`

- `coreAppGridItems` 改为陪伴页：
  - `聊天`
  - `日记`
  - `世界`
  - `音乐`
  - `相册`
  - `日历`
  - `一起读`
  - `我的`

- `extraAppGridItems` 改为系统页：
  - `接口`
  - `同步`
  - `权限`
  - `外观`
  - `更新`
  - `日志`

### `client/src/components/AppDrawer.tsx`

需要调整：

- 删除第一层 `API设置`、`商城`。
- `apps` 改成陪伴语义：
  - `聊天`
  - `日记`
  - `世界`
  - `音乐`
  - `相册`
  - `日历`
  - `一起读`
  - `我的`
  - `接口`

- 搜索区文案从 `Search apps...` 改成 `搜索聊天、日记或世界书`。
- Daily Intention 改成今日关系状态，例如：`今天适合慢慢说话`。
- 底部状态从 `STORAGE` 改成 `SYNC` 或 `MEMORY`，不要暴露存储百分比。

### `client/src/components/HomeWidgets.tsx`

需要调整：

- `DaysMatterWidget` 不再是考试倒计时。
- 改成：
  - 上方：`在一起`
  - 中间大数字：`477`
  - 下方：`DAYS`
  - 辅助：`最近日记 130 篇 / 消息 4494 条`

- 新增或改造状态 Widget：
  - `AIStatusWidget`：清醒 / 睡眠 / 被吵醒 / 情绪。
  - `WeatherContextWidget`：用户所在地天气。
  - `NextMomentWidget`：下一次约定或主动消息窗口。

### `client/src/components/MemoryManagerApp.tsx`

当前页是开发调试用的“数据管理”。必须从用户入口中移走，或者改造成用户可见的日记页。

用户可见结构：

- 顶部：`日记`
- 统计：消息总数、日记总数、在一起天数。
- 列表：按日期平等罗列日记。
- 收藏馆：只放用户收藏或系统判定的重要记忆。
- 每篇日记可进入详情，详情里可以看到相关聊天片段，但不要展示 RAG、队列、API 操作。

底层仍然可以写入 memories 表：

- `source = diary.memory`
- `weight`
- `time`
- `role`
- `Wing`
- `Room`
- `tags`
- `isPinned`
- `isRetrievable`

这些字段不直接暴露给普通用户。

### `client/src/components/NotesApp.tsx`

应明确为 `世界` 页面，不是普通 Notes。

页面层级：

- `角色`
  - 名字、称呼、头像、声线、回应边界。
- `关系`
  - 亲密节奏、主动消息规则、睡眠/起床、情绪注入。
- `世界书`
  - Wing / Room / 条目。
  - 条目可增删改。
  - 可绑定到角色。
- `偏好`
  - 用户雷点、喜欢的语气、禁区。

### `client/src/components/SettingsApp.tsx`

系统设置可以保留完整，但应改为“我的 / 系统”语义：

- `我的`
  - 账号
  - 云同步
  - 加群 / 社区
  - 检查更新
  - 记录保存策略

- `高级`
  - 模型接口
  - MCP 授权
  - 本地数据库
  - 日志
  - 导入导出

注意：MCP 是外部能力开关，不是陪伴主模块。

## 五、功能主链路

用户发消息后：

1. 理解 query。
2. 按当前角色、Wing、Room、关系状态过滤记忆范围。
3. 从本地记忆库做 RAG 检索。
4. 用权重、时间、重要度、日记来源进行 rerank。
5. 组装 prompt。
6. 模型回复。
7. 自动写入可检索记忆。
8. 晚间工作流生成日记，并作为高权重记忆源写入。

用户不需要知道 `MemPalace / RAG / MCP` 这些词。

## 六、验收标准

1. 首页第一眼是陪伴关系，不是后台工具。
2. 桌面第一层没有 `API设置`、`数据管理`、`MCP`、`RAG`、`数据库`。
3. 聊天入口最快到达，且状态栏/输入框保持吸顶吸底。
4. 日记页只展示日记、历史日期、收藏馆。
5. 世界页可编辑角色、人设、世界书、关系规则。
6. 音乐、相册、日历、位置是生活场景能力，不是抽象模块。
7. 高级接口、同步、更新、导入导出都在系统层。
