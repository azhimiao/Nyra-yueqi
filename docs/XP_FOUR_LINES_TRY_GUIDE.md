# 四条创作体验线 · 试玩与验收指南

> 更新：2026-07-28  
> 当前定级：四条产品主循环 `implementation_green`，本地合同、浏览器旅程与生产构建通过；真实模型长局质量、真机手感和用户审美仍需人工验收。

## 四条线不是四种皮肤

| 入口 | 产品语义 | 用户在做什么 | 不能退化成什么 |
|---|---|---|---|
| **情景** | 角色驱动的开放式 RP | 选角色、作品与开场，自由行动；人格、世界书、记忆和历史共同决定后续 | 固定剧情树、关键词命中后播预制台词 |
| **漫卷** | Galgame / 视觉小说播放器 | 按句阅读，看背景与立绘变化，选择分支，管理历史与存档 | 另一张聊天页或换色卡片 |
| **冒险** | AI DM 驱动的持续世界 | 用行动、说话、检定推进地图、任务、状态和物品 | 恋爱对话套一张地图，或模型失败时偷偷播假剧情 |
| **共创** | 长篇写作工作台 | 管项目、章节、正文、大纲和故事圣经；对 AI 候选做接受或拒绝 | 陪伴聊天、三轮样例或一键覆盖正文 |

桌宠只属于系统级陪伴入口，不作为这四种工具的头像、剧情幕布或占位插画。

## 1. 情景：开放式角色演出

入口：小手机 Dock → **情景**。

1. 选择作品、同一个长期角色和三个开场之一。
2. 自由输入行动或台词；建议行动只是辅助，不是固定分支按钮。
3. 对任意消息使用编辑、重生成、候选切换和创建分支。
4. 切回旧分支，确认旧世界线没有被后续重生成污染。
5. 主动谢幕后，只有已接受的当前世界线可投影为共同经历。

验收重点：正式模型不可用时保留原输入并给出重试，不出现“离线试演”把旧节点剧情拼进当前会话。

## 2. 漫卷：视觉小说

入口：小手机桌面 → **漫卷**。

1. 从作品库进入《雨线以外》，选择第一章。
2. 按“下一句”确认旁白、角色立绘、背景和对白层按剧本切换。
3. 检查自动播放、已读快进、阅读回顾、隐藏界面、静音与阅读设置。
4. 为三个存档槽命名并保存；刷新后读取任一存档。
5. 在选择点走不同分支，确认中段和结局均不合流。

验收重点：背景必须真实加载；快进在未读句前停止；素材缺失要明确提示，不能拿桌宠动作帧当舞台占位。

## 3. 冒险：AI 跑团

入口：小手机桌面 → **冒险**。

1. 作品库先区分正式世界与明确标记的本地教程。
2. 进入正式世界，选择开场与玩家身份。
3. 分别使用“行动 / 说话 / 检定”，确认三者进入不同 DM 语义。
4. 模型结果先显示为候选；接受前地图、任务、时间、属性和背包不得变化。
5. 接受后查看效果落库，再从历史回合创建另一条世界线。

验收重点：正式世界没有模型时必须诚实失败；DM 只能返回合同允许的效果，非法 JSON、未知效果或不存在的分叉回合必须拒绝。

## 4. 共创：长篇写作工作台

入口：小手机桌面 → **共创**。

1. 在项目库新建或打开作品，编辑章节正文。
2. 在章节之间快速切换，刷新后确认正文不丢失。
3. 编辑章节梗概、人物表和世界设定，立即切换页面后再回来检查。
4. 选中正文后调用续写、改写或扩写；候选出现前正文不变。
5. 接受候选只替换选区并生成快照；拒绝则正文完全不变。
6. 调整章节顺序，导出时确认故事圣经与全文顺序一致。

验收重点：所有编辑字段分别保存，不能由一个共享防抖计时器互相覆盖；无模型时不伪造离线改稿。

## 自动验收

```powershell
npm run verify:creative-modes
$env:DEMO_URL='http://127.0.0.1:5174'; npm run e2e:creative-modes
npm run build
```

当前基线：剧情 `84/84 + 60/60 + 67/67 + 7/7 E2E`，漫卷 `61/61 + 13/13 E2E`，冒险 `23/23 + 15/15 E2E`，共创 `16/16 + 15 项 E2E`。

## 仍不能宣称完成的门

- 真实聊天 Provider 下，情景三个开场各至少 30 轮的角色一致性与开放续写质量。
- 正式冒险世界的真实 DM 长局稳定性、数值平衡与上下文预算。
- Windows / Android 真机上的触控、键盘、安全区、后台恢复和 30 分钟连续使用。
- 用户对美术、文案节奏和总体手感的签署。

这些门未通过前，不能把 `implementation_green` 写成“已达到竞品”或 `user_accepted`。
