## 0. 一句话

**栖市**是月栖里可安装、可更新、可组合的「体验应用」市场：把情景剧、漫卷、冒险、共创、游戏，以及能挂进 Pop 的轻游戏插件，做成一套可生长的生态，而不是写死在桌面里的几个入口。

---

## 1. 为什么做

月栖已有「今晚一起演戏 / 共创 / 游戏」等形态，Float 类产品也证明用户需要多种 **AI 演出姿态**：

| 姿态 | 用户感知 | AI 角色 |
|------|----------|---------|
| 演一场戏 | 情景剧 | AI 演「这场戏」 |
| 演一部 Gal | 漫卷 | AI 演「这部 Gal」并吐帧 |
| 推一张地图 | 冒险 | AI 当 DM，自己推地图事件 |
| 合写一本书 | 共创 | AI 当合著者，自己动章节档 |
| 玩一把局 | 游戏 / 插件 | AI 当主持、NPC 或裁判 |

若不做成生态，这些会沦为：

1. 桌面图标堆砌；
2. 每个品类各写一套孤岛；
3. 创作者无法分发更新；
4. Pop 里的骰子 / 狼人杀等「聊天内游戏」无法复用。

栖市的目标是：**同一套安装 / 权限 / 更新 / 组合机制，服务多种演出姿态。**

---

## 2. 产品边界

### 2.1 栖市是什么

- 小手机内的 **应用市场 + 本地安装器**。
- 体验包（Experience Pack）与插件包（Pop Plugin）的 **发现、安装、更新、启停、卸载** 面。
- 创作者与用户之间的 **分发层**（可先本地 / 侧载，后接签名商店）。

### 2.2 栖市不是什么

| 不是 | 说明 |
|------|------|
| 不是应用设置页 | 配置仍在各 App / 系统设置 |
| 不是角色商店 | 角色包、世界包另走创作者通道；栖市可「推荐组合」，但不吞并角色分发 |
| 不是公网联机大厅 | V1 默认单机 / 本机多会话；联机另立项 |
| 不是任意 WebView 沙盒 | 只跑月栖登记过的运行时契约，禁止裸网页当 App |

## 3. 体验品类（货架分类）

栖市货架按 **用户要过的夜晚** 分类，而不是按工程模块名。

### 3.1 演出类（AI 在演）

| 品类 ID | 对用户名 | 一句话 | AI 姿态 | 主界面 |
|---------|----------|--------|---------|--------|
| `theater` | 情景剧 | 今晚这场戏 | 演员 / 轻导演 | 舞台 Stage |
| `scroll` | 漫卷 | 这部 Gal | 演 Gal 并吐帧 | 帧阅读器 + 选项 |
| `adventure` | 冒险 | 这张地图 | DM，推地图事件 | 地图 / 事件卡 |
| `cocreate` | 共创 | 这部作品 | 合著者，改章节档 | 作品画布 + 会话 |

规则：

- 四类都是 **可安装的体验应用**（或同一运行时上的「模式包」），不是四个死图标。
- 可共享：角色注入、世界书、记忆回写、谢幕 → 日记 / 生命事件。
- 不可混为一谈：漫卷吐帧 ≠ 情景剧舞台；冒险推图 ≠ 共创写档。

### 3.2 游戏类（AI 在主持或旁观）

| 品类 ID | 对用户名 | 一句话 | 形态 |
|---------|----------|--------|------|
| `game` | 游戏 | 独立玩法 App | 完整界面（棋盘、回合、结算） |
| `pop-plugin` | 聊天插件 | 挂在 Pop 里玩 | 单聊 / 群聊工具条与会话内交互 |

游戏在栖市里与演出类并列上架；**细分出插件**，专门服务「以聊天为主场」的玩法。

### 3.3 插件子类（Pop 优先）

插件默认 **不抢全屏 App**，而是进入 Pop：

| 例子 | 场景 | 宿主 |
|------|------|------|
| 投骰子 | 单聊 / 群聊 | Pop 工具条 + 气泡结果 |
| 狼人杀 | 群聊局 | 群会话面板 + 阶段播报 |
| 真心话 / 惩罚转盘 | 单聊或群聊 | 轻量面板 |
| 剧本杀线索板 | 群聊 | 侧栏 / 半屏 |

规则：

- 插件必须声明宿主：`dm` | `group` | `both`。
- 插件可唤起「完整游戏 App」，但主路径应在会话内完成一局或一次动作。
- 插件不得冒充系统助手或桌宠人格；发言走「局内身份」或「系统旁白」契约。

## 4. 用户旅程

### 4.1 发现 → 安装 → 打开

```
桌面「栖市」或 设置 / 创作者入口
        │
        ▼
┌────────────────┐
│ 栖市货架        │  演出 / 游戏 / 插件 · 搜索 · 更新
└────────┬───────┘
         │ 安装体验包或插件
         ▼
┌────────────────┐
│ 已安装         │  打开 / 更新 / 权限 / 卸载
└────────┬───────┘
         │
    ┌────┴────┐
    ▼         ▼
 独立 App   Pop 工具条出现插件
（情景剧等） （骰子 / 狼人杀）
```

### 4.2 与现有旗舰体验的关系

| 现有入口 | 栖市之后 |
|----------|----------|
| 桌面「情景剧」 | 可保留为 **系统预装** 的 theater 运行时；更多剧本/模式从栖市更新 |
| 「共创」 | 预装 cocreate 壳；作品模板 / 合著策略包可上架 |
| 「游戏」 | 重游戏走独立 App；轻游戏优先插件化进 Pop |
| Dock / Pop | Pop 成为插件主战场；桌宠仍不承载系统货架 |

原则：**预装提供第一晚能玩；栖市提供以后还能长。**

## 5. 包与运行时契约

### 5.1 两种包

| 包类型 | 内容大致 | 安装后去哪 |
|--------|----------|------------|
| **Experience Pack** | 品类、UI 壳或模式、资源、提示词策略、权限声明 | 桌面图标或「演出中心」列表 |
| **Pop Plugin Pack** | 插件 ID、宿主、工具条入口、会话协议、可选完整 App 回跳 | Pop 工具条 / 群能力栏 |

角色包、世界包、皮肤包 **不属于栖市核心货架**（可交叉推荐），避免「人格商店」与「玩法商店」混权。

### 5.2 每个包必须声明

1. **品类**（theater / scroll / adventure / cocreate / game / pop-plugin）  
2. **能力面**：可读哪些上下文（角色卡、世界书、当前会话、群成员列表…）  
3. **写入面**：可写哪些（会话消息、局状态、章节档、地图存档、生命事件…）  
4. **确认门**：哪些写入要用户点头  
5. **更新通道**：版本号、兼容的宿主版本  
6. **离线策略**：无网能否继续本局 / 本幕  

### 5.3 AI 姿态合同（产品语言）

| 品类 | 允许 AI 主动做什么 | 不允许 |
|------|-------------------|--------|
| 情景剧 | 推进场次、给选项、演角色对白 | 偷偷改用户世界书正文 |
| 漫卷 | 吐下一帧、立绘/背景指令、分支 | 跳过用户确认的付费/敏感帧策略（若有） |
| 冒险 | 生成地图事件、判定、推进时钟 | 无存档地抹掉长期进度 |
| 共创 | 改章节草稿、提结构建议、版本对比 | 未经确认覆盖「已发布」定稿 |
| 游戏 App | 主持规则、结算 | 读写无关会话隐私 |
| Pop 插件 | 在局内发言、改局状态 | 伪装成用户、刷屏骚扰、越权改群公告 |

## 6. Pop 插件深度定义

### 6.1 为什么插件独立于「游戏 App」

- 骰子、狼人杀的主场是 **对话节奏**，不是独立大厅。  
- 用户已在单聊 / 群聊里；再跳进另一个 App 会打断「和 TA / 和朋友一起」。  
- 插件把「玩法」嵌进 Pop，把「重度界面」留给可选的完整游戏。

### 6.2 插件生命周期

```
安装 → 在 Pop 工具条可见
  → 用户在某会话启用本局
  → 插件写入「局状态」（本地）
  → 气泡 / 半屏 / 系统旁白推进
  → 结束本局 → 可选写入生命事件 / 群摘要
  → 卸载插件时清理局状态（可保留历史摘要）
```

### 6.3 单聊 vs 群聊

| | 单聊 DM | 群聊 Group |
|--|---------|------------|
| 典型 | 骰子、双人小游戏、和 TA 玩规则互动 | 狼人杀、多人本局、投票 |
| AI 角色 | 常作为对手 / 裁判 / TA 入戏 | 常作为主持人 / 旁白 / NPC |
| 权限 | 角色上下文强 | 成员列表、发言权、阶段锁 |

### 6.4 与情景剧 / 冒险的组合（远期）

允许声明 **组合安装**：例如「冒险包 + 骰子插件」，冒险里的判定调用同一套骰子协议，避免两套随机规则。

## 7. 信息架构（栖市 App）

```
栖市
├── 发现（精选 / 演出 / 游戏 / 插件）
├── 搜索
├── 更新（有更新的已安装项）
├── 已安装
│     ├── 体验应用
│     └── 聊天插件
└── 创作者（侧载、本地包、我的上架草稿）— 可后置
```

桌面策略建议：

- **栖市** 一个入口进货架。  
- 高频预装（Pop、情景剧、一起听…）仍可钉在桌面 / Dock。  
- 从栖市新装的体验，默认进「已安装」；用户可「放到桌面」。

## 8. 生态角色

| 角色 | 诉求 | 栖市提供 |
|------|------|----------|
| 普通用户 | 多一种今晚的玩法 | 安装、更新、权限可读 |
| 深度用户 | 组装自己的夜晚 | 插件 + 体验组合、桌面钉选 |
| 创作者 | 分发剧本模式 / 玩法 | 打包契约、版本、侧载 → 日后签名商店 |
| 月栖官方 | 品质与安全 | 预装、精选、权限审计、杀毒级策略（无任意代码） |

---

## 9. 成功标准（产品级）

1. **用户能说清**：栖市是「装玩法的地方」，不是第二个设置。  
2. **四种演出姿态**在货架上可被识别，且安装后体验不像「换皮聊天」。  
3. **至少一个 Pop 插件**（如投骰子）在单聊可用；**至少一个群插件**（如狼人杀骨架）可开局。  
4. **更新不丢档**：更新漫卷 / 冒险 / 共创包后，进行中的存档可迁移或明确提示。  
5. **权限可见**：安装页写清「能读什么、能写什么」。  
6. **不污染桌宠**：桌宠仍是陪伴角色，不出现「去应用市场」系统话术。

---

## 10. 刻意不做（V1）

- 开放任意第三方 JS 注入 Pop。  
- 未签名远程热更新可执行逻辑（资源包可，逻辑需过契约）。  
- 把角色卡商店做进栖市主 Tab。  
- 强制所有游戏只能插件化（重游戏仍可独立 App）。  
- 用栖市替换情景剧 / 共创已有旗舰路径（只叠加分发与扩展）。

## 11. 分期建议（定义级，非排期承诺）

| 阶段 | 交付物 |
|------|--------|
| **E0 契约** | Experience / Plugin manifest、权限枚举、本地安装卸载 |
| **E1 货架壳** | 栖市 App：发现占位、已安装、侧载本地包 |
| **E2 演出上架** | 情景剧 / 漫卷 / 冒险 / 共创 以「可更新包」挂到同一运行时 |
| **E3 Pop 插件** | 投骰子（DM）+ 狼人杀最小局（Group） |
| **E4 生态** | 精选、更新通道、创作者侧载规范、组合推荐 |

## 13. 一句话收束

**栖市 = 月栖的体验生态层**：演出类负责「AI 怎么演」，游戏 App 负责「完整玩法」，Pop 插件负责「聊着就能玩」；三者共用安装与权限契约，让情景剧、漫卷、冒险、共创和骰子/狼人杀长在同一棵树上，而不是四个互不相认的入口。
