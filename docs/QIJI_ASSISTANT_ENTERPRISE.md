# 栖机助手企业级能力合同

## 1. 产品语义

栖机助手是月栖的系统操作台，不是恋爱角色、桌宠人格或另一个聊天对象。

用户描述想达到的效果，助手负责：

1. 识别当前页面和用户目标。
2. 读取必要状态并解释影响。
3. 调用月栖已登记的本地能力。
4. 把写入或删除操作交给用户确认。
5. 返回真实执行结果，并留下可核查的本地记录。

“企业级”不等于模型可以随意改任何数据，而是每项能力都有明确合同、权限等级、确认门和失败回执。

## 2. 当前能力面

能力目录是代码中的单一事实源：`src/studio-assist/registry.js`。

## 3. 权限与执行规则

| 等级 | 行为 | 用户确认 |
| --- | --- | --- |
| `read` | 读取已授权的本地业务状态 | 不需要 |
| `action` | 打开页面或切换界面 | 不需要 |
| `write` | 新建、修改、启停或切换数据 | 必须确认 |
| `destructive` | 删除数据 | 必须显示删除风险并强确认 |

模型输出的 `confirm`、`confirmed` 等字段没有授权效果。确认只由本地 UI 产生，能力网关收到本地确认标记后才执行。

每次真实执行都会写入本地审计记录。参数中的 `apiKey`、`secret`、`token`、`password`、`authorization` 等字段在落库前强制脱敏。支持撤销的工具同时写入最小回滚描述。

## 4. 月栖协议

模型只负责提出结构化意图：

```text
<yq-pack name="character" />
<yq-tool name="character.update">{"id":"角色ID","patch":{"persona":"新的设定"}}</yq-tool>
```

协议不直接赋权。解析器只接受登记过的工具 ID；未知工具拒绝执行，非法 JSON 返回协议错误。

## 5. 全局入口

- App 模式：桌面侧栏和手机底栏提供一级“栖机助手 / Nyra Assistant”入口；每个设置详情页另有“问助手”，并携带当前页面上下文。
- 小手机模式：状态栏机器人图标在任意已解锁应用中可用，打开系统助手并携带当前应用上下文。
- 能力导航：助手可打开已登记的小手机应用或设置详情。
- 桌宠：不承载栖机助手。桌宠继续只表达长期陪伴角色，避免系统人格与角色人格混淆。

## 6. 语言合同

助手不维护独立语言开关，始终跟随月栖的全局 `zh-CN / en` 选择。切换语言必须同步更新：

- 主导航、手机底栏、小手机入口和设置页入口。
- 助手标题、欢迎语、能力目录、快捷请求、输入框和安全说明。
- 读取结果、错误信息、写入确认卡、取消与完成回执。
- 发给模型的系统提示、当前页面上下文和能力网关反馈语言。

英文模式下名称为 `Nyra Assistant`。工具 ID、领域 ID 和 `yq-pack / yq-tool` 协议保持语言中立，避免语言切换破坏能力调用。

## 7. 刻意禁止的能力

以下不是“以后忘了做”，而是企业级安全边界：

- 不让模型读取、显示或修改任何 API Key、令牌和密码。
- 不允许模型注入任意 CSS、脚本或未审查的 HTML；外观只能调用经过产品验证的主题能力。
- 不在没有原生权限和明确授权时读取屏幕、文件、通讯录、照片或系统日历。
- 不自动发布朋友圈、发送外部消息、购买商品、付款或公开内容；这些高影响动作必须由专用工作流和最终用户确认承担。
- 不把系统助手伪装成恋爱角色，也不让角色绕过系统审批。

## 8. 验收门

本地合同验收：

```text
npm run verify:studio-assist
```

必须证明：

- 能力目录不少于 15 个领域、40 项工具。
- 写入未确认时不改变存储。
- 确认后才产生真实写入。
- 审计对密钥形字段脱敏。
- 最近一次可逆写入可撤销。
- `yq-pack / yq-tool` 能稳定解析。
- 没有模型配置时给出明确引导，不伪造执行结果。
- 中文和英文系统提示都包含密钥保护、确认门和语言响应约束。
- 两种语言的能力目录、上下文欢迎语、无 Key 引导和写入确认均有合同测试。

浏览器验收还需覆盖桌面和移动视口、所有设置页入口、小手机全局入口、确认/取消态，以及控制台零未处理错误。
