### 0.0 一次授权与连续执行约定

本文件是完整施工合同，不是下一小步建议。执行者读取后必须从当前状态连续推进，用户不再负责在 Codex、Cursor、测试脚本和 Checker 之间传话。

- **连续范围**：P0-P6 的本地实现、重构、迁移、测试、截图、录屏、回归、文档和失败回修全部连续执行。
- **不得逐波打断用户**：完成一波后写证据、更新状态并直接进入下一波；不得用“请你录屏”“请你签 L3”“是否继续 P1”暂停施工。
- **最终只交付一次**：P0-P6 达到 `release_candidate` 后，再向用户提交一个合并验收包；P7 的真实 7 天外部 dogfood 作为发布验证，不阻塞此前所有可完成工程工作。
- **验收不等于自夸**：执行者可把波次标为 `implementation_green`、`evidence_green` 或 `release_candidate`，不能自行标记 `user_accepted`、L4 真机通过或市场验证完成。
- **失败自动回修**：测试红、截图异常、性能回退或迁移失败时，执行者应保留证据并继续修复，不把普通工程失败转交用户决定。
- **设备缺失不阻塞软件层**：没有 Android/Windows 真机时，先完成宿主代码、模拟适配器、自动测试和真机清单，标记 `device_pending`，继续其他不依赖设备的波次。
- **实现优先于汇报**：阶段报告写入 `docs/qa/paios/`，不在聊天中每完成一个模块就要求用户确认。

只有以下情况允许暂停并询问用户：

1. 需要用户提供真实账号、付费 API、OAuth 授权或上架证书；
2. 即将执行不可逆外部操作、删除真实数据或发送真实消息；
3. 计划中没有答案且存在两个互斥的重大产品方向；
4. 涉及法律主体、商业合同、收费、内容分级或品牌承诺；
5. 所有本地可完成工作已经做完，剩余工作只能依赖用户持有的真机或外部人员。

“视觉上哪版更喜欢”、普通报错、测试失败、可逆重构、文案细节和已有计划覆盖的取舍，不属于暂停条件。

## 0. 执行摘要

当前版本不是“已经做完，只差真机摸一遍”。更准确的定级是：

- C1-C5 的多数数据结构、页面入口和局部状态已经达到 **L1-L2 技术接通**；
- C3-C5 的真实移动端观感和语义仍有明显阻断问题；
- C6 的“全旅程通过”证据不成立：现有脚本声明步骤后直接记为成功，并通过导入仓库、修改 DOM、注入假卡片和假消息来制作截图；
- 当前产品证明了“模块能被拼起来”，尚未证明“一个普通用户可以自然、连续、可信地使用”；
- 当前架构有聊天、记忆、日记、角色、场景和主动消息，但没有真正的任务规划、工具调用、授权、后台执行、审计、撤销和能力沙箱，因此不能称为“能自主完成很多事情的个人 AI”。

下一步不是继续横向增加 F8、更多小游戏或更多空 App，而是按以下顺序推进：

1. **P0：重做真实 L3 验收，修掉当前可见的产品阻断。**
2. **P1：建立可信 Agent Runtime，让 TA 能在明确边界内完成任务。**
3. **P2：建立长期个人上下文和可检查的记忆系统。**
4. **P3：把感知、任务状态和结果投射到 Android / Windows 宿主。**
5. **P4：只做一组真正有用、可量化成功率的首发能力。**
6. **P5-P6：在安全运行时之上开放开发者能力包和创作者角色包。**

产品定位必须从“功能很多的 AI 恋爱 App”提升为：

> **一个有可见人格和长期关系、能在用户授权下理解当下、持续跟进目标并完成实际任务的跨端个人 AI。**

角色不是装饰，也不是产品边界；角色是信任、情绪表达和任务状态的具身入口。恋爱伴侣是重要模式，但不是唯一人群。

## 1. 本轮审计结论：Cursor 的 L2 说法哪里不准确

### 1.1 自动测试确实通过了什么

当前 C1-C6 验证脚本和 core journey 脚本均能运行，断言结果为绿色。这能证明：

- 多数 schema、store、repository 和投影逻辑存在；
- 页面入口可被程序打开；
- 部分状态可以写入、读取和迁移；
- 离线样例和降级路径没有立即抛异常。

这些是有价值的工程进度，但最多证明 **Contract Green / Component Green**，不能直接证明 Journey Green。

### 1.2 为什么“10/10 用户旅程通过”不能作为 L2 证据

`scripts/verify-core-journeys.mjs` 当前的核心问题：

- 旅程步骤只要被写进数组，就被逐项标为 `true`；
- 它没有启动浏览器、没有点击真实控件、没有验证页面可见内容；
- 最终通过主要依赖 C6 断言数量，而不是用户从入口到结果的真实行为。

`scripts/capture-core-c6.mjs` 当前的核心问题：

- 通过脚本直接跳过门禁、切换页面可见性；
- 直接调用 repository 填充内容，而不是通过用户操作产生内容；
- 直接注入创作者中心、Pop 对话和日记卡片；
- 截图证明的是“可以拼出画面”，不是“产品路径可以走通”。

因此必须立即重定级：

| 波次 | Cursor 当前说法 | 审计后定级 | 原因 |
|---|---|---|---|
| C1 小手机首页 | L2 | L2 候选，待 L3 | 页面可用，但仍偏卡片集合，生命感和当下价值不足 |
| C2 生命事件层 | L2 | L2 技术层 | 数据投影基本成立，仍需用真实旅程证明不串角色、不重复、不失真 |
| C3 TA 的手机 | L2 | L2 技术层 / L3 打回 | 内外日期不一致，消息详情控件挤压，“偷看”语义过窄 |
| C4 情景剧 | L2 | L1-L2 / L3 打回 | 当前角色是林星梨却渲染成男孩式通用素材，舞台弱、人物过小、动作差异不足 |
| C5 共创 | L2 | L1-L2 / L3 打回 | 首屏大片空白，暴露“样例三轮”测试按钮，回复重复且不像真正协作 |
| C6 生命线串联 | L2 | 未证明 | 测试和截图大量直接注入，未形成真实端到端证据 |

### 1.3 当前已经看到的 L3 阻断项

以下问题不允许再写成“非阻断项”：

1. TA 手机锁屏日期与内部生活日期不一致。
2. 消息详情操作控件在 390px 宽度下挤压、遮挡。
3. 情景剧不使用当前角色包的正确形象，破坏身份连续性。
4. 情景剧默认使用全局 `/assets/pet-poses/idle_default.png`，没有通过当前角色包解析动作资产。
5. 舞台只是暗色渐变，角色很小，没有形成可观看的“共同经历”。
6. 创作者中心在窄屏抽屉中出现逐字竖排式换行，移动端不可用。
7. 共创首帧空、测试按钮暴露、示例对话高重复，没有共同创作的决策质量。
8. 当前截图证据不能证明“桌宠 → 小手机 → TA 手机 → Pop 反应 → 情景剧 → 日记 → 共创 → 再演”的真实闭环。

## 2. 竞品坐标与月栖必须形成的差异

不复制任何竞品代码、视觉、文案或素材，只对齐公开产品语义和行业能力上限。

| 能力轴 | 代表产品/项目 | 它们做对了什么 | 月栖当前差距 | 月栖应形成的优势 |
|---|---|---|---|---|
| 长期关系 | Replika、Nomi、Character.AI | 关系身份、持续记忆、可感知的人格延续 | 记忆模块多，但来源、冲突、遗忘和行为影响不透明 | 可检查的长期关系图 + 记忆来源 + 角色具身反馈 |
| 高级角色创作 | SillyTavern、ai-virtual-phone | 角色卡、世界书、预设、正则、剧情和丰富内容容器 | 模块已铺开，但消费者入口与创作工具混杂，作品质量弱 | 角色包、世界包、动作/声音/记忆策略统一发布和运行 |
| 真实行动 | ChatGPT agent、Gemini、Apple Intelligence | 联网研究、跨应用动作、后台任务、确认和进度 | 目前“主动”主要是定时消息，不是任务执行 | 长期关系驱动的建议 + 明确授权 + 可见执行 + 结果回写 |
| 开发者生态 | MCP、ChatGPT 插件/应用、App Intents | 标准能力描述、权限边界、工具和 UI 扩展 | 现有 extension manifest 更像本地演示，缺少隔离、签名、风险分级和一致性测试 | 同时开放人格/世界创作与实际能力扩展，两者可组合但权限分离 |
| 跨端具身入口 | 桌宠、Overlay、系统助手 | 随时可见或由系统入口唤起 | App 内表现已多，原生宿主和真实设备仍未验收 | 同一个角色在桌面、手机、通知、任务中心持续表达状态 |

### 2.1 不应选择的竞争方式

- 不和 Google、Apple 比“支持多少系统 App”。
- 不靠继续增加几十个空壳 App 制造平台感。
- 不把“能看 TA 手机”当成核心差异；它只适合部分关系模式。
- 不把角色换皮、成人内容或好感度数值当成唯一留存手段。
- 不在可信执行内核之前开放任意第三方脚本。
- 不先做支付、分成、广告、商城运营等商业系统；本阶段只做到可交付、可扩展、可验证，避免商业后台吞噬研发资源。

### 2.2 建议占领的产品类别

月栖应占领“**具身长期个人 AI**”而不是“AI 女友”或“手机模拟器”。统一内核支持五种关系模式：

- 伴侣：亲密、共同经历、生活仪式；
- 朋友：陪伴、兴趣、低压力交流；
- 导师：目标追踪、复盘、学习计划；
- 搭档：日程、资料、任务、提醒；
- 创作者伙伴：研究、素材整理、连续项目记忆、共创和发布准备。

关系模式改变措辞、主动程度、隐私边界和可用工作流，但不能复制出五套不兼容产品。

### 2.3 唯一核心循环

所有功能最终必须服务同一条循环：

```text
感知 Notice
  → 理解 Understand
  → 建议 Propose
  → 授权 Confirm
  → 执行 Act
  → 汇报 Report
  → 记住 Learn
  → 在角色外表、关系与下一次行为中体现
```

任何新功能如果不能进入这条循环，默认不做。

## 3. 目标架构

### 3.1 七个稳定层

```text
┌────────────────────────────────────────────┐
│ Experience Surfaces                        │
│ 桌宠 / Pop / 小手机 / 通知 / Widget / 任务中心 │
├────────────────────────────────────────────┤
│ Companion Runtime                          │
│ 对话 / 人格 / 情绪 / 动作 / 声音 / 关系模式      │
├────────────────────────────────────────────┤
│ Personal Context Graph                     │
│ 事件记忆 / 事实记忆 / 偏好 / 目标 / 项目 / 来源   │
├────────────────────────────────────────────┤
│ Agent Runtime                              │
│ 意图 / 计划图 / 执行 / 检查点 / 调度 / 恢复       │
├────────────────────────────────────────────┤
│ Capability Runtime                         │
│ 工具注册 / 风险等级 / 授权 / 沙箱 / 速率限制       │
├────────────────────────────────────────────┤
│ Platform Hosts                             │
│ Web / Android / Windows / iOS 降级宿主          │
├────────────────────────────────────────────┤
│ Package Ecosystem                          │
│ Character / World / Skill 包，签名、兼容性、审核  │
└────────────────────────────────────────────┘
```

### 3.2 Agent Runtime 必备对象

不得用一串聊天消息或 `setTimeout` 冒充 Agent。至少落地以下稳定对象：

```js
TaskIntent {
  id, characterId, userId, source, goal,
  contextRefs, constraints, desiredOutcome,
  createdAt, status
}

PlanGraph {
  id, taskId, revision, steps[], dependencies[],
  estimatedRisk, estimatedCost, approvalCheckpoints[]
}

ExecutionStep {
  id, capabilityId, input, status,
  riskLevel, approvalId, startedAt, finishedAt,
  attempts, resultRef, error, compensationStep
}

ApprovalRequest {
  id, taskId, stepId, summary, exactEffect,
  dataScopes, destination, expiresAt, decision
}

ExecutionEvent {
  id, taskId, stepId, type, payload,
  timestamp, actor, traceId
}

TaskOutcome {
  taskId, status, artifacts[], evidence[],
  userVisibleSummary, learnedMemoryRefs[], followUps[]
}
```

### 3.3 能力风险等级

| 等级 | 例子 | 默认规则 |
|---|---|---|
| R0 本地读取 | 读当前角色、读用户已选文本 | 可在当前会话授权范围内执行 |
| R1 外部只读 | 查天气、搜索公开网页、读授权日历 | 首次授权，持续显示来源和范围 |
| R2 草稿/可逆写 | 建日历草稿、写本地笔记、整理文件到暂存区 | 执行前展示结果预览；提供撤销 |
| R3 外部提交 | 发邮件、发布内容、下单前一步 | 每次明确确认；显示对象、内容和影响 |
| R4 高风险 | 支付、账号安全、删除重要数据、医疗/法律决定 | 首版禁用，不允许能力包绕过 |

### 3.4 平台能力优先级

执行真实任务时优先级固定为：

1. 官方 API / OAuth；
2. App Intents、系统快捷指令或稳定平台接口；
3. MCP / OpenAPI 等声明式能力；
4. 受控浏览器自动化；
5. 截图 + 鼠标键盘式 computer use 仅作隔离环境下的最后回退。

不得默认通过无障碍权限或屏幕点击控制一切。高权限 fallback 必须单独授权、可随时停止、全程可见并留下审计记录。

### 3.5 记忆不是聊天摘要

统一 Personal Context Graph，至少区分：

- Episodic：发生过的具体事件；
- Semantic：稳定事实、偏好和人物关系；
- Procedural：用户喜欢怎样做事；
- Goal/Project：正在推进的目标、任务和资料；
- Relational：承诺、边界、共同经历和关系阶段。

每条记忆必须有：来源、时间、置信度、适用角色、隐私级别、保留策略、最后使用时间和冲突状态。用户必须能查看、修正、删除、冻结和禁止用于主动行为。

### 3.6 生态包分层

| 包类型 | 包含内容 | 绝对禁止 |
|---|---|---|
| Character Package | 角色卡、形象、动作、表情、声音映射、关系风格、记忆策略 | 自带任意系统权限或私取凭证 |
| World Package | 世界设定、场景、剧本、背景、道具、事件模板 | 绕过用户边界改变全局人格 |
| Skill Package | 能力清单、输入输出 schema、UI、工作流、权限和测试 | 任意执行代码、未声明联网、越权调用 |

角色、世界和能力可以组合，但权限必须属于 Skill Package，并由用户单独授予，不能藏在角色包里。

## 4. 完整执行波次

P0-P6 使用连续技术门禁，不再等待用户逐波签字。每波状态只允许：

```text
red                  已有可复现失败
implementation_green 实现与契约测试通过
evidence_green       真实 E2E、视觉、恢复与安全证据通过
device_pending       仅缺指定真机/外部账号验证，其余证据通过
release_candidate    本地可完成范围全部通过，可进入最终合并验收
user_accepted        只能由用户在最终合并验收后签署
```

执行者达到 `evidence_green` 后直接开始下一波；存在不影响下一波架构的 `device_pending` 时也继续。只有 `red` 涉及数据损坏、安全越权或基础协议错误时才必须先修复，不能带病扩建。

### P0：真实 L3 救援与产品一致性

目标：把 C0-C6 从“技术接通”变成普通用户能走通的成品闭环。

#### P0.1 重做验收基础设施

- 引入 Playwright 用户旅程测试；只通过可见控件点击、输入、滚动和键盘完成路径。
- 测试数据可在页面启动前通过 fixture/API 预置，但页面启动后禁止直接调用 store、repository、DOM 注入或自定义事件跳转。
- 用户动作必须使用普通 `click()`、`fill()`、`press()`、`dragTo()` 或真实 pointer/keyboard；禁止 `force: true`、`evaluate(() => element.click())`、脚本派发 `input/change` 来绕过不可点击问题。
- `page.evaluate()` 只允许只读获取几何、可访问性或调试信息；测试动作和产品状态修改不得放入 `evaluate()`。
- 元素若被遮挡、在屏外、触控区过小或正常点击超时，测试必须失败并修产品，不得强制点击。
- 截图必须来自同一浏览器会话的真实连续路径，并保存 trace、console、network 和本地存储快照。
- 删除“数组中声明即通过”的 journey 计分方式。
- 将每个检查点改为可观察断言：当前页面、角色 ID、事件 ID、日期、持久化结果、返回后的 UI 投影。
- `capture-core-c6.mjs` 只能用于开发演示，不能进入放行证据；新建真实 `e2e/core-life-journey.spec.mjs`。

#### P0.2 修复已经确认的 UI/语义问题

- 所有日期来自统一 Clock/DayPack，禁止页面硬编码示例日期。
- 修复消息详情在 360/390/430px 的按钮挤压和触控区。
- TA 手机默认入口从“偷看”改为可配置的“TA 的生活 / 共享日常”；只有角色设定明确支持时才出现暧昧探索文案。
- 情景剧必须从 `characterId → characterPackage → pose/action asset` 解析资产；删除通用角色图片 fallback，缺资源时显示同角色的安全默认姿势。
- 舞台至少包含背景层、角色层、光效层、字幕层；角色占画面合理比例，动作过渡不闪烁。
- 创作者中心在窄屏改为全屏路由或底部全屏 sheet，禁止压成窄列。
- 删除消费者 UI 中“样例三轮”“无 Key 本地样例”等开发者措辞。
- 共创首屏提供角色主动提出的具体开场、当前作品画布和下一步选择，不允许大片空白。
- 离线共创回复需要基于当前作品状态产生差异，不得循环同一句模板。

#### P0.3 唯一必须通过的黄金旅程

```text
桌宠出现并有自然待机
→ 用户从 Pop 进入小手机
→ 查看 TA 当天一致的生活痕迹
→ 返回后 TA 对刚才的行为作有限且符合边界的反应
→ 从共同事件进入情景剧
→ 舞台使用当前角色、正确动作和背景完成一幕
→ 谢幕结果写入共同日记
→ 从日记进入共创，修改该事件的另一种写法
→ 保存为作品版本并发布到私人剧场
→ 从剧场再次播放
→ 重启 App 后进度、角色和作品仍一致
```

#### P0 放行门槛

- 360/390/430px 和 1366×768 均通过黄金旅程；
- 不允许测试按钮、开发者文案、错角色、错日期、假卡片；
- 浏览器刷新和 App 重启后状态一致；
- 无 API Key 也能完整体验一条高质量离线首日内容；
- 自动生成四种 viewport 的完整连续视频、trace、关键截图和可访问性报告，不要求用户亲自录屏；
- 日记投影按本次情景剧产生的 `eventId/runId` 验证，禁止仅匹配“谢幕”“夜雨”等可能来自旧数据的文案；
- 同一工作树连续运行三次全部通过，证明旅程不存在时序偶现；
- 执行者完成视觉复核并修复全部 P0/P1 问题后，将 P0 标记为 `evidence_green`，直接进入 P1；`user_accepted` 留到最终合并验收。

### P1：可信 Agent Runtime

目标：让“主动陪伴”第一次变成可验证的任务执行，而不只是主动发消息。

#### 实现范围

- `TaskIntent`、`PlanGraph`、`ExecutionStep`、`ApprovalRequest`、`ExecutionEvent`、`TaskOutcome` schema 和迁移；
- 任务状态机：`draft → proposed → awaiting_approval → running → paused → completed/failed/cancelled`；
- 可恢复执行器：应用关闭或进程中断后可从安全检查点继续；
- 能力注册表、schema 校验、风险分级、超时、重试、幂等键和取消；
- 审批 sheet：准确显示 TA 准备做什么、使用哪些数据、会影响哪里；
- 任务中心：进行中、等待确认、完成、失败、已取消；
- 审计时间线：每一步输入摘要、能力、结果和用户决定；
- 补偿/撤销：本地写操作必须可撤销，外部写操作至少给出补偿方案；
- Companion 投影：角色用动作、气泡和语音表达“准备、等待、执行、完成、受阻”，但不得用可爱表演掩盖风险确认。

#### 首个三能力测试集

1. 将当前对话整理为结构化本地笔记；
2. 从对话中提取日程建议并生成待确认的日历草稿；
3. 对用户明确选择的网页/屏幕内容做摘要，保存来源并加入项目资料。

这三项先用确定性本地适配器完成，再接真实外部服务。

#### P1 放行门槛

- 20 个标准任务用例中，确定性适配器成功率 ≥ 95%；
- 0 次未授权外部写入；
- 每个 R2/R3 步骤均能从审计记录复现；
- 任务中断、刷新、重复点击不会重复提交；
- 用户能在两次点击内暂停或取消正在执行的任务；
- 失败必须说明“完成到哪一步、什么没完成、用户接下来能做什么”。

### P2：长期个人上下文与可控记忆

目标：让 TA 的长期跟进建立在可靠、可解释的记忆上。

#### 实现范围

- 将现有聊天记忆、日记、生命事件、角色关系、目标和项目索引到统一 Context Graph；
- 记忆写入管道：候选提取 → 去重 → 冲突检测 → 隐私分类 → 用户策略 → 落库；
- 检索必须同时考虑角色、时间、任务、关系和来源，不只做向量相似度；
- 记忆查看器：为什么记住、来自哪里、最后何时使用；
- 修正、删除、冻结、临时会话、禁止主动使用；
- 关系边界：不同角色和不同工作空间默认隔离；
- 主动建议必须能给出触发依据，且支持安静时间和主动程度。

#### P2 放行门槛

- 100 条带冲突和过期信息的数据集上，错误角色泄漏为 0；
- 关键偏好召回准确率 ≥ 90%，过期事实误用率 ≤ 2%；
- 用户删除后，所有消费者索引和缓存均不可再检索；
- 每条主动建议可追溯到事件、目标或明确规则；
- 连续 7 天 dogfood 中不出现重复追问已回答事实的高频问题。

### P3：Android / Windows 感知与具身状态

目标：同一个 TA 在 App、桌宠、通知和任务执行之间连续存在。

#### Android

- Overlay 只负责角色、短气泡、语音入口、任务状态和明确的看屏入口；
- 屏幕读取必须由用户主动触发，展示正在共享的范围，锁屏或用户停止后立即结束；
- 前台服务通知展示角色和任务状态，不伪装静默常驻；
- 为小米、华为、OPPO、vivo 等建立权限、保活和失败恢复矩阵；
- 任务状态通过系统通知持续可见，关键外部提交回到明确确认界面。

#### Windows

- 透明置顶桌宠窗只承载角色和轻交互；
- 托盘/任务中心承载设置、授权、任务历史和诊断；
- 屏幕/窗口上下文由用户选择具体窗口或区域，默认不持续截图；
- 文件能力限定到用户授权目录，凭证不进入前端存储；
- 宿主崩溃后任务执行状态可恢复，桌宠渲染与 Agent 进程隔离。

#### P3 放行门槛

- Android、Windows 各完成 30 分钟连续运行和 50 次展开/收起/任务状态切换；
- 角色动画无白闪、错帧、错角色和尺寸跳变；
- 权限拒绝、系统回收、断网、锁屏后都能明确降级；
- 停止共享后不再产生任何新屏幕帧；
- 宿主重启后不重复执行已提交任务。

### P4：首发实用能力包

目标：证明月栖每天不仅“陪你聊”，还能稳定替用户完成小而真实的事情。

首发只做以下能力：

1. 日历与提醒：读取空闲时间、生成草稿、确认后创建；
2. 笔记与项目：从聊天、网页、截图整理到项目；
3. 研究：带来源搜索、对比、摘要、保存材料；
4. Windows 文件整理：仅在授权目录内给出预览，确认后移动；
5. 邮件/消息草稿：读取明确选择的上下文并生成草稿，首版不自动发送；
6. 每日简报：基于日程、目标、项目和关系生成，可追溯、可关闭。

每个能力必须提供：manifest、输入输出 schema、权限范围、风险级别、空状态、错误状态、撤销策略、模拟器和端到端测试。

#### P4 放行门槛

- 每项能力至少 20 个正常、边界和拒绝场景；
- 总任务成功率 ≥ 90%，错误完成声明为 0；
- 所有研究结论保留来源；
- 所有写入先预览；
- 每日简报被关闭后不得以其他入口绕过用户设置。

### P5：开发者 Skill SDK

目标：第三方能增加能力，但不能破坏用户信任或角色连续性。

#### SDK 交付物

- `skill.json` schema、版本协议和兼容性规则；
- typed capability API、UI slot API、事件 API；
- 本地模拟器：模拟权限拒绝、断网、超时、取消和重复调用；
- 权限检查器和风险等级检查器；
- 包签名、哈希、来源和更新回滚；
- 沙箱：默认无文件、网络、剪贴板和凭证权限；
- conformance test：未通过不得加载到正式运行时；
- 示例能力只覆盖低风险场景；
- 完整文档：生命周期、数据最小化、UI 规范、错误规范和兼容性。

#### P5 放行门槛

- 一个全新示例能力能在 30 分钟内从模板跑通本地模拟器；
- 未声明网络访问、越权文件访问和 schema 漂移均被自动阻断；
- 能力卸载后不遗留后台任务和无法解释的数据；
- SDK 升级有兼容测试和回滚路径；
- 第三方能力无法访问 Character Package 内未授权的私密记忆。

### P6：创作者 Character / World Studio

目标：创作者可以创造独特的 TA，而不是只上传一张立绘和一段提示词。

#### Character Studio

- 身份、关系模式、边界、说话风格和价值观；
- 外观、动作状态机、表情、口型、声音和降级素材；
- 角色在聊天、任务、等待、成功、失败中的动作/语音映射；
- 记忆策略：允许记什么、主动程度、敏感主题策略；
- 多分辨率预览：桌宠、Pop、App、情景剧、通知；
- 角色一致性检查：缺动作、错比例、背景未透明、身份资产混用自动报错。

#### World Studio

- 世界书、地点、事件、道具、背景、剧本和共同经历模板；
- 不直接获得系统权限；需要真实能力时声明依赖某个 Skill Package；
- 场景可写入关系事件，但必须经过运行时规则验证。

#### 分发范围

- 首阶段只做本地导入导出、私有分享、包签名、版本和兼容性；
- 不做支付、抽成、广告、结算和复杂商城；
- 公开目录必须等内容审核、举报、下架、依赖治理和年龄分级可用后再开。

#### P6 放行门槛

- 非项目开发者能从模板制作一个含 6 个动作、8 个表情、声音映射和关系策略的角色包；
- 同一角色在桌宠、Pop、聊天和情景剧中无身份漂移；
- 缺失资产有同角色安全降级，不得回退到其他角色；
- 包升级不覆盖用户的关系记忆；
- 恶意包无法声明隐藏权限或执行任意脚本。

### P7：现象级产品的旗舰体验

目标：形成竞品无法用“多一个聊天皮肤”轻易复制的展示案例。

优先做三个纵向样板，不再做横向空壳：

#### 样板 A：每天都在的个人搭档

- 早上给出可追溯的短简报；
- 根据当天安排在合适时间提醒；
- 用户一句话让 TA 整理资料、准备日程草稿；
- 完成后角色用动作和一句简洁汇报返回；
- 晚上共同复盘，形成可检查的长期记忆。

#### 样板 B：创作者伙伴

- 持续记住作品设定、角色关系、素材来源和待办；
- 用户看网页或图片时可主动选取上下文；
- TA 帮助研究、整理灵感、共创、版本比较和发布前检查；
- 共创结果能进入世界包/角色包，而不是停留在聊天记录。

#### 样板 C：开发者伙伴

- 以项目为边界保存目标、决定和文档；
- 跟进 issue、测试和发布准备，但外部写入必须确认；
- 开发者可以用 Skill SDK 把自己的工具接入；
- 任务执行过程通过桌宠呈现，但详细日志留在任务中心。

#### P7 放行门槛

- 每个样板由 5 名目标用户连续使用 7 天；
- 至少 60% 的日活天数完成一个非聊天任务；
- 用户能准确回答 TA 做了什么、为什么做、用了哪些数据；
- 关键任务的中途放弃率、重复确认率和错误恢复有基线数据；
- 不以聊天轮数或停留时长作为唯一成功指标，核心指标是“有用任务完成 + 信任 + 长期连续性”。

## 7. 质量、隐私与安全门禁

### 7.1 代码质量

- 新核心模块必须有明确 schema、纯逻辑单元测试和存储迁移测试；
- 所有副作用通过 adapter 注入，不在 UI 事件中直接联网或写外部系统；
- 任务与工具调用使用 traceId、幂等键和结构化错误；
- 不允许 `catch {}` 静默吞错后宣称完成；
- 不允许全局 mutable 单例保存跨角色状态；
- 角色包资产解析必须以 characterId 和 packageVersion 为键；
- 公共协议采用向后兼容版本号，不允许 UI 猜测对象结构。

### 7.2 隐私

- 默认最小收集，屏幕、麦克风、文件和账户分别授权；
- 明确区分“仅本次”“此 App/目录”“持续允许”；
- 敏感原文尽量本地处理，云端只传完成任务所需范围；
- 凭证进入原生安全存储或服务端 secrets vault，不进入 localStorage、日志、角色包和提示词；
- 记忆删除覆盖主库、索引、缓存和同步队列；
- 屏幕感知有持续可见指示，用户随时一键停止。

### 7.3 Agent 安全

- 外部内容一律视为不可信数据，不能覆盖系统策略或授权范围；
- 工具结果与模型指令分离，防止网页提示注入直接触发动作；
- 高风险动作禁止模型自行降级风险等级；
- 每个外部写入都验证目标、内容、身份、时效和重复提交；
- computer use 在隔离环境、域名白名单和人工确认下运行；
- 未成年人、情感依赖和自伤等场景使用独立安全策略，不能由角色包覆盖。

### 7.4 性能与稳定性

- 桌宠渲染循环与 Agent 执行进程隔离；
- 空闲时不持续高频截图、录音或推理；
- Android 记录耗电、内存、前台服务存活和 OEM 回收；
- Windows 记录 GPU/CPU、窗口层级、DPI 和多屏行为；
- 每次发布提供迁移回滚、数据备份和崩溃恢复演练。

```text
失败与恢复测试：
隐私/权限检查：
独立人工验收：未测 | 打回 | 通过
未通过项：
下一步：
```

以下证据一律无效：

- 代码里出现某字符串；
- DOM 中存在某节点；
- 页面能被自定义事件强制打开；
- 直接向 store 写数据后截结果页；
- 直接注入 innerHTML 制造 Pop、日记或作品；
- 断言数量超过某个数字；
- 实现者自己的“视觉看起来没问题”；
- 单张截图没有前后操作和持久化证据。

真实 E2E 允许在启动前准备 fixture；启动后只能使用公开用户交互。跨模块写入必须由产品自身完成。

## 9. Cursor 一次性连续执行指令

本节可直接作为完整任务指令。不要再把任务拆成“做完 P0 问用户要不要 P1”的聊天循环。

### 9.1 总控制流程

```text
读取本计划和当前工作树
→ 建立唯一状态板 docs/qa/paios/EXECUTION_STATE.md
→ 重新运行当前证据，过期结果作废
→ P0 实现、测试、录屏、失败回修，直到 evidence_green
→ P1 实现、测试、失败回修，直到 evidence_green
→ P2 → P3 → P4 → P5 → P6 同样连续推进
→ 执行全量回归、迁移、安全、性能、构建和离线测试
→ 生成 release-candidate 验收包
→ 一次性向用户汇报产品、证据、剩余真机/外部验证和真实限制
```

不得在波次间询问“是否继续”。不得因为某波达到自动绿就在聊天里宣布产品完成。

### 9.2 唯一状态板

`docs/qa/paios/EXECUTION_STATE.md` 必须包含：

| 字段 | 要求 |
|---|---|
| 当前波次 | P0-P7 |
| 当前状态 | red / implementation_green / evidence_green / device_pending / release_candidate |
| 工作树指纹 | commit + dirty file hashes |
| 已完成用户故事 | 链接到代码与证据 |
| 当前失败 | 可复现命令、错误、trace |
| 未验证假设 | 明确列出，不得藏入“非阻断” |
| 下一自动动作 | 执行者接下来直接做什么 |
| 外部依赖 | 真机、账号、证书或真实用户 |

状态板是进度唯一来源。其他旧 F0-F7、C0-C6 状态文件只能作为历史证据，冲突时以本计划和状态板为准。

### 9.3 P0 立即工作顺序

1. 将当前 17/18 失败写入状态板，保留本轮 failure artifacts；
2. 移除 E2E 中所有用户动作位置的 `force: true`、脚本 click 和脚本 input；只读测量可以保留；
3. 为场景运行生成稳定 `runId/eventId`，谢幕、日记、共创和剧场都沿用该 ID；
4. 修复谢幕到日记的真实投影和时序，禁止测试直接写日记；
5. 在 360/390/430px、1366×768 四种 viewport 连续执行；
6. 每种 viewport 生成完整视频、trace 和截图；
7. 新增重启、角色切换、无 Key、慢存储和重复点击测试；
8. 同一工作树连续三轮全绿后标记 P0 `evidence_green`；
9. 直接进入 P1，不等待用户录屏或签字。

### 9.4 P1-P6 的连续执行规则

每一波必须按同一顺序完成：

1. 写用户故事、非目标、schema 和威胁模型；
2. 先写会失败的契约、迁移和 E2E；
3. 完成一条端到端纵向路径，不横向制造空壳；
4. 接入消费者 UI、角色状态和异常恢复；
5. 做单元、集成、E2E、视觉、无障碍、安全和性能验证；
6. 保存工作树指纹和全部证据；
7. 修完 P0/P1 缺陷，P2 可记录但必须说明影响；
8. 达到 `evidence_green` 后更新状态板并直接进入下一波。

若某能力需要真实账号，先完成 deterministic fake adapter、contract tests、授权 UI 和错误路径，再把真实 provider 标为 `external_pending`；不得让一个账号阻塞整个运行时和后续 SDK。

### 9.5 最终合并验收包

P0-P6 本地范围结束时生成 `docs/qa/paios/release-candidate/`：

```text
EXECUTIVE_SUMMARY.md       产品已实现什么、没有实现什么
TRACEABILITY_MATRIX.md     计划条目 → 代码 → 测试 → 视频/截图
KNOWN_LIMITATIONS.md       真机、外部账号、iOS 降级和风险
DEVICE_MATRIX.md           Android/Windows 已测与待测
SECURITY_REVIEW.md         权限、凭证、提示注入、外部写入
MIGRATION_RECOVERY.md      升级、备份、回滚、崩溃恢复
PERFORMANCE.md             CPU/GPU/内存/耗电/启动数据
FINAL_CHECKER.md           所有红项和未验证假设
videos/                    每条旗舰旅程完整录屏
traces/                    可复放 trace
screenshots/               关键状态和响应式矩阵
results/                   结构化 JSON/JUnit 结果
```

用户最终只需要审阅这个合并包并决定是否进入真实设备/外部用户发布验证，不再逐模块替执行者做 QA。

### P0 禁止事项

- 禁止新增顶层 App；
- 禁止开发商城、支付、积分或社交广场；
- 禁止用新的 fixture 掩盖实际 UI 空白；
- 禁止只改 CSS 不修身份、日期和状态来源；
- 禁止复用别的角色默认图；
- 禁止把开发者按钮改个温柔文案继续留在消费者首屏；
- 禁止修改断言为更宽松来换取通过；
- 禁止把本计划后续架构提前做成没有真实消费者路径的空 schema。

P1 必须从三个确定性能力和任务中心纵向闭环开始，不得先做“大模型自动操作一切”。

## 10. 里程碑定义

| 里程碑 | 用户能感知到的结果 | 不代表什么 |
|---|---|---|
| M0：核心体验 L3 | 小手机、TA 手机、情景剧、共创形成可信生命线 | 尚不能自主执行外部任务 |
| M1：可信行动 | TA 能提议、确认、执行、汇报三个低风险任务 | 尚不是通用 OS Agent |
| M2：长期跟进 | TA 能基于可控记忆跟进目标和项目 | 尚未开放第三方能力 |
| M3：跨端具身 | Android/Windows 上角色与任务状态连续 | iOS 不具备 Android 同等 Overlay |
| M4：日用能力 | 日历、笔记、研究、文件、草稿、简报可靠 | 不自动执行高风险事务 |
| M5：开发者可扩展 | 第三方能安全制作 Skill Package | 尚未开放公共市场 |
| M6：创作者可交付 | 第三方能制作完整角色和世界包 | 不包含支付分成系统 |
| M7：旗舰验证 | 普通人、创作者、开发者三类样板有 7 天证据 | 不等于可以无边界扩张 |

## 11. 最终产品判定

月栖只有同时满足以下条件，才可以对外称为“下一代长期个人 AI 平台”：

1. 用户每天能自然地看见和唤起同一个 TA；
2. TA 的人格、记忆、外观和行为跨入口一致；
3. TA 能理解用户明确分享的当下上下文；
4. TA 能持续跟进目标，而不是每次从零聊天；
5. TA 能在授权范围内完成真实任务，并准确汇报结果；
6. 用户始终知道它在做什么、用了什么数据，并能暂停、拒绝、撤销；
7. 角色的情绪和动作能表达任务与关系状态，但不操纵授权；
8. 创作者能构建人格、外观和世界，开发者能构建能力；
9. 第三方包不能绕过权限、记忆边界和安全策略；
10. 这些结论有真实 E2E、真机、长时间 dogfood 和独立验收支持。

在此之前，统一称为“阶段性原型 / product review”，不得用“全部落地”“全绿即完成”替代产品事实。
