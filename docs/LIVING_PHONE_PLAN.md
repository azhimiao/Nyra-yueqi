# 月栖 · 栖机世界计划（Living Phone）

> 品牌：**月栖**（英文 **Nyra**）  
> 日期：2026-07-25  
> 原则：本地优先、能力自研、可验收切片、**开源友好（clean-room）**  
> 关联：[MULTI_CHARACTER_PLAN](./MULTI_CHARACTER_PLAN.md) · [SCENARIO_THEATER_PLAN](./SCENARIO_THEATER_PLAN.md) · [FEATURE_EXPANSION_PLAN](./FEATURE_EXPANSION_PLAN.md)  
> 阶段 Prompt：[docs/align/](./align/)（模板 + F0–F7）

本计划描述月栖「小手机 / 栖机」要建成的**完整能力面**：让角色像住在一部会自己运转的手机里。  
实现一律自写；对照笔记若存在，仅允许留在开发者本机私有目录，**不得**进入开源发布物、git 子模块或产品打包。

## 4. 工程约束

1. **Clean-room：** 只对齐交互语义与信息架构；禁止粘贴外部对照实现代码进入本仓库。  
2. **本地优先：** 云能力全部可关；单机可玩完 F0–F6 主路径。  
3. **一波一 verify：** 每波至少一个 `scripts/verify-align-fN.mjs`（按波挂入 `npm run verify`）。  
4. **不做项锁死：** D2 D7 D8 E2 E3 E4 G4 出现在 PR 视为范围违规。  
5. **侧写广度：** F2c 允许「池子大、每角色桌面抽选约 8 个图标」，不强制全开。  
6. **阶段节奏：** 先「详细化 Fn」扩满 [align/Fn.md](./align/)，再「执行 Fn」写代码；一次只做一个阶段。  
7. **质量门槛强制：** 凡标记「已落地」的波次，必须同时满足 [align/_QUALITY_BAR.md](./align/_QUALITY_BAR.md)（UI U1–U12、工程 E1–E10、语义 P1–P3）与该 Fn §9 专属条款。功能可用但观感/工程半成品 = **未完成**。

## 5. 如何使用阶段 Prompt

1. 读本文件确认范围与用语。  
2. 打开对应 [align/Fn.md](./align/F0.md)；若仍为骨架，先发指令 **「详细化 Fn」** 扩成可执行 Prompt。  
3. 详细化时 **必须** 把 [_QUALITY_BAR.md](./align/_QUALITY_BAR.md) 写入该 Fn §9，并写成可逐步照做的手测路径（禁止一句「手测通过」）。  
4. 将完整 Fn 文件作为一次 Agent Prompt，或发 **「执行 Fn」** 落地。  
5. 模板见 [align/_PROMPT_TEMPLATE.md](./align/_PROMPT_TEMPLATE.md)。
