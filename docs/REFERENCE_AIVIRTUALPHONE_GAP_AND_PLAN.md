## 0. 一句话结论

参考端是：**同一角色人生上的多种体裁玩法**（选角色 → 进局 → 按协议玩 → 记忆回流）。  
月栖现状是：**同名桌面图标 + 各自半截壳**（入口能开，闭环不成，体裁互抢心智）。

差距不在「有没有图标」，而在：

1. **交互闭环**（lobby → play → 产出）是否成立；  
2. **体裁协议**（帧 / 故事文 / DM 地图 / 合写确认 / 可运行包）是否独立；  
3. **角色绑定 + 记忆回流**是否把六个 App 缝进同一人生。

## 3. 分 App 完整交互区别

### 3.1 漫卷（VN）

#### 参考闭环

```
打开漫卷 → VnSelect 选角色（无角色：请先创建）
       → VnChapters 选/续章节
       → VnPlayer 点屏 advance 播帧（场景/立绘/旁白/对白）
       → 帧尽：选项 或 自由输入
       → generateVnCompletion → vn-parser 解析为帧+选项 → 继续播
       → 可归档章节 / 打开资源库管立绘
```

关键文件：`components/vn/vn-app.tsx`、`vn-player.tsx`、`lib/vn-engine.ts`、`lib/vn-parser.ts`、`lib/vn-asset-storage.ts`

#### 月栖闭环（现状）

```
打开漫卷 → 作品库（内置固定短篇）
       → 选章 → 点屏读预设 frames
       → 选项走分支 → 结局
       → 无「选角色开局」、无 AI 吐帧主路径
       → 立绘：正式素材未交付时占位（已禁止桌宠图）
```

关键文件：`src/scroll/player-ui.js`、`src/scroll/presets.js`、`src/scroll/schema.js`

#### 逐项对照

| 项 | 参考 | 月栖 | 判定 |
|----|------|------|------|
| 开局 | 角色 | 作品 | 错位 |
| 内容来源 | AI 按协议生成帧 + 历史 | 内置静态剧本 | 错位 |
| 立绘 | 用户/资源库，按角色 | 缺省占位；曾误用桌宠 | 未对齐 |
| 续写 | 选项 + 自由输入 → 新帧 | 仅预设选项 | 缺能力 |
| 章节 | 按角色会话归档/总结 | 按作品解锁章 | 部分类似外壳 |
| 手感 | Gal / 视觉小说 | 短篇点读器 | 体裁弱 |

**对齐目标（月栖产品语言）：** 漫卷 =「和这个角色演一部 Gal」：选角色 → 章节 → 帧阅读器；AI 吐帧；立绘永不走桌宠包。

### 3.2 剧情 / 情景

#### 参考「剧情」闭环

```
打开剧情 → 角色列表（空则引导创建）
       → 点角色 → createOrGetStorySession
       → 底部输入；空态：「故事从这里开始」
       → generateStoryCompletion → story-parser → HTML 故事气泡
       → 可停生成、编辑消息、主题
```

关键文件：`components/story/story-app-base.tsx`、`lib/story-engine.ts`、`lib/story-parser.ts`

#### 月栖「情景」闭环（现状）

```
打开情景 → 选同行者 → 选开场/章节点
       → 舞台对话 + 选项 + 偶发自由输入（情景剧管线）
       → 依赖模型与情景包；无角色时易空
```

关键文件：`src/scenario/player/player-ui.js`、情景剧相关 runtime

#### 逐项对照

| 项 | 参考剧情 | 月栖情景 | 判定 |
|----|----------|----------|------|
| 用户心智 | 和 TA 写/读一段长文故事 | 今晚演一场戏（舞台） | **两套产品** |
| 主 UI | 会话气泡（故事文） | 舞台 Stage | 不同 |
| 开局 | 角色 | 角色 + 剧本包 | 更重 |
| 与漫卷边界 | 清晰：长文 vs 帧 | 都像「故事」，易混 | 危险 |

**对齐策略（二选一，计划里定案）：**

- **A（推荐对齐参考）：** 月栖「情景」改名为对用户更清晰的「剧情」或保留「情景」但改成**角色故事会话**；现有舞台剧能力降级为栖市可装的 `theater` 包或高级入口。  
- **B（保留舞台）：** 桌面同时只保留一个「故事向」消费入口；舞台与漫卷用文案硬切开，禁止双入口同页抢心智。

```
       → 文字主日志 + 行动/说话输入 + 侧栏档案
```

关键文件：`src/adventure/player-ui.js`、`src/adventure/dm.js`、`src/adventure/presets.js`

#### 逐项对照

| 项 | 参考 | 月栖 | 判定 |

**对齐目标：** Lobby 造/选世界 → **地图或强空间 UI** → 事件选项优先、自由输入为辅 → DM 协议；教学局保留。

#### 参考闭环

```

       → WRITE / TALK 模式与角色会话

```

## 4. 用户第一眼为什么看不懂（根因清单）

1. **六个入口，三种「故事」心智**（漫卷点读 / 情景舞台 / 冒险文字）未切开。  
2. **名字对齐参考，玩法未对齐**（最伤：漫卷、共创、栖市）。  
3. **开局不是「找她」而是「找包」**，与聊天主路径断裂。  
4. **空态说开发者话**（侧载 zip），不说下一步生活动作。  
5. **无跨 App 人生感**：聊完去冒险，冒险不像接得上。  
6. **桌宠图污染漫卷**加深「这不是独立玩法」的印象（引用已拆，素材债仍在）。

## 5. 完整对齐计划

### 5.0 原则（硬约束）

1. **只对齐产品语义与通用交互规律**；禁止复制参考源码、CSS、素材、提示词、独特文案。  
2. **每波只打通一条纵向闭环**（入口 → 可玩 → 可保存 → 可回流），禁止横向再堆壳。  
3. **桌宠 / 头像 / VN 立绘 / 情景舞台立绘** 命名空间隔离（已有政策，执行验收）。  
4. **无 Key / 无角色** 必须有高质量离线引导或教学局，禁止空白「去生成」。  
5. 消费者桌面不暴露接口、正则、SDK、举报后门（高级进设置/创作者页）。

### 5.1 目标态（对齐后用户心智）

| App | 一句话怎么玩 | 开局 | AI 角色 |
|-----|--------------|------|---------|
| 漫卷 | 选她 → 读 Gal 帧；选项或说话续写 | 角色 | 吐帧演员 |
| 剧情（现情景改造或拆分） | 选她 → 像写信一样把故事聊下去 | 角色 | 故事叙述/角色 |
| 冒险 | 造/选世界 → 地图探索 → 选项或宣言 | 世界+同伴 | DM |
| 游戏 | 点已装游戏 →（需 AI 则选角）→ 玩 | 游戏包 | 可选主持 |
| 栖市 | 发现/安装 → 桌面多图标 | 市场 | 无 |
| 共创 | 选她+作品 → 对话合写 → 确认写入章节 | 角色+作品 | 合著者 |

### 5.2 阶段划分

#### Phase 0 — 定界与减负（0.5–1 周）

**目标：** 停止心智污染，定案命名。

| 任务 | 验收 |
|------|------|
| 定案：情景 vs 剧情（策略 A 或 B，见 §3.2） | 书面定案进本文档修订记录 |
| 桌面文案统一「怎么玩」一行（已部分做） | 六个入口副标题无「合写/探索」等歧义打架 |
| 漫卷禁止任何桌宠/pet-poses/错误头像路径 | grep + 人工打开确认无全身桌宠立绘 |
| 文档：本对照为唯一体验对齐依据之一 | 链到 `APP_MARKETPLACE_ECOSYSTEM.md` |

**交付物：** 修订后的命名表；桌面文案；资产隔离检查清单。

#### Phase 1 — 漫卷体裁对齐（P0，1.5–2.5 周）

**目标：** 漫卷成为「角色 Gal」，不是短篇库。

| 里程碑 | 内容 | 验收 |
|--------|------|------|
| M1.1 | 开局改为**选角色**（无角色 → 引导去角色页） | 无角色无法进入空播放器 |
| M1.2 | 会话/章节按 `characterId` 存储 | 换角色章节不串 |
| M1.3 | 帧协议：模型输出 → 解析为 frames + options（可先简版 parser） | 错误输出有降级提示，不崩 |
| M1.4 | Player：点屏推进；帧尽出选项/输入 | 与参考同构的操作，不抄 UI |
| M1.5 | 立绘/场景：独立资源命名空间；缺省占位 | 永不回退桌宠 |
| M1.6 | 内置短篇改为「示范章」或迁入教学包 | 不挡角色开局主路径 |

**参考只读：** `vn-app` 三态机、`vn-engine`/`vn-parser` 的协议形状（自研实现）。  
**非目标本阶段：** 完美立绘编辑器、双语、完整归档 UI。

#### Phase 3 — 冒险地图手感（P0/P1，2–3 周）

#### Phase 4 — 共创语义纠正（P0，1.5–2 周）

**目标：** 默认「和她合写」。

| 里程碑 | 内容 | 验收 |
|--------|------|------|
| M4.1 | 开局强制选角色 + 作品 | 无角色不能默认为纯写作台 |

| M4.5 | 合写记忆投影 | 最小一条 |


建议开工顺序：**0 → 1 → 2 → 4 → 3 → 5**，记忆横切从 Phase 1 起埋点。

---

### 5.4 每阶段通用验收（Definition of Done）

对每个 App，必须同时满足：

1. **无角色 / 无 Key：** 有明确引导或离线教学，不白屏。  
2. **有角色 + 有 Key：** 5 分钟内完成一次「进局 → 互动 → 看到体裁产物」。  
3. **保存：** 杀掉进程再开能续。  
4. **边界：** 用户能一句话说清它和另外五个的区别。  
5. **资产：** 无桌宠图冒充实立绘。  
6. **禁止**用「路由能开 / DOM 在」当完成证据。
