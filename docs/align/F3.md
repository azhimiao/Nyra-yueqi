## 4. 产品语义（月栖用语，交互长什么样）

### 4.1 一起听（D3）— `[data-phone-screen="listen"]`

**现状（phone-shell）：** 已有 stage（角色圆盘 + 曲名 + 歌单名 + 波形装饰）+ 曲目列表 `[data-phone-tracks]`，但 **无真实播放控件**，曲目行 **不可点**，与 App 版 `co-listen.js` **未接线**。

**目标交互：**

1. 栖机 Home → 点 **一起听**（`apps-catalog.js`：`id: listen`，Dock 默认有）。
2. **Stage 区（主视觉）：**
   - 顶栏：`一起听` / 副标题 `同步此刻`；左返回 Home。
   - 中部：角色头像圆 + 「正在一起听」badge；**大曲名** + 歌单名；**进度条**（可拖）+ 当前时间 / 总时长；**播放 / 暂停** 主按钮（≥ 44px，三态：playing / paused / loading）。
   - 底部：**共听** Switch（默认开）；关时仍本地可播，但不注入 Pop / 外部上下文。
3. **曲目列表：** 每行：tone 渐变封面 tile + 曲名 + 歌单元信息；**点击切歌**并自动播放；当前曲 `is-active` 高亮；空列表空态「歌单还空着」+ 文案「可在生活库导入本地音频」。
4. **播放反馈：** 切歌 / 暂停 / 恢复时，可选在 Pop 线程插入系统条（复用 `formatCoListenChatNotice`，与 App 版一致）；共听开时 `buildExternalContext` 能读到 `formatCoListenContextLine`。
5. **持久化：** 杀页重进 → 恢复上次曲目 + `positionSec`（误差 ≤ 2s）；最近播放写入 `yueqi.recentPlays.v1`。
6. **与 App 版同步（可选但推荐）：** 复用 `co-listen-sync.js` BroadcastChannel，栖机与浏览器 App 模式 tab 可同步进度（无第二 tab 时不报错）。

**动效：** 播放时 stage 波形 `mini-wave` 有 subtle 动画；`prefers-reduced-motion` 时静态（U5）。

### 4.2 一起看（D4）— `[data-phone-screen="read"]`

**现状：** 书架 `[data-phone-books]` 渲染 `phoneData.listBooks()`，**点击书籍无阅读器**；App 版有完整 `book-reader.js`（滚动阅读 + 划选 + 意见 sheet）。

**目标交互：**

1. Home → **一起看**（`id: read`，`page: 2`）。
2. **书架页：** 2–3 列书脊卡片（已有 `book-shelf-card`）；每本显示进度标签（`待读` / `已读 42%` / `第 12 章`）；空态「书架还空着」。
3. **阅读器页（本波新增栈层）：** 顶栏：‹ 返回书架 + 书名 + 进度%；正文区 `white-space: pre-wrap` 段落滚动；底部：**继续共读**（发 Pop 消息，复用 `formatContinueCoReadMessage`）+ 可选划选 → 引用 sheet（可简化为「告诉 TA 这段」按钮 + 当前段落 excerpt）。
4. **进度：** 滚动停止 500ms 后保存 `scrollRatio` 到 `library.books[]` 对应书；同时 `saveCoReadAnchor`（`yueqi.coReadAnchor.v1`）；退出再进 **滚动位置恢复**。
5. **与 App 版：** 同一 `yueqi.library.v1` 书籍数组；media 正文走 `getMediaRecord` / `readMediaBlob`（与 `book-reader.js` 相同 deps 模式）。

**禁止：** 只做书架不做阅读器；或进度仅存内存。

### 4.3 日历（D5）— `[data-phone-screen="calendar"]`

**现状：** `createPhoneCalendar` + `phone-data.addEvent` + 添加表单已可用；`proactive/scheduler.js` 已读 `library.events`；缺：**事件类型 hint UI**、**保存后 reschedule**、**栖机内快捷模板**（同步听歌 / 共读）。

**目标交互：**

1. Home → **日历**。
2. **月历首页：** 月切换；今日高亮；有事件日期 `has-event` 点；下方 **日 sheet** 列出当日事件（时间 + 标题 + prompt 摘要 + 删除）。
3. **添加页：** 标题、日期（跟月历选中联动）、时间 chip（默认 21:00）、**事件说明** textarea；**快捷模板 chip** 三组：`提醒` / `同步听歌` / `共读` — 点后自动填 title + prompt（走 `event-types.js` 的 `LEGACY_TYPE_PROMPTS` 语义，存储仍 `type: generic` + 富 prompt）。
4. **主动模式：** 表单项保留 hidden `mode: 可主动消息`（与现有 seed 一致）；保存后 toast「已保存」并 **调用 `rescheduleProactiveScheduler()`**（若 global deps 已挂载）。
5. **到点行为：** scheduler 触发 `runProactiveAction` → Pop 消息或栖息通知；DND 时段（`notificationSettings.dndStart/dndEnd`）遵循现有 `isWithinDnd`；用户关「主动消息」feature 时不调度。
6. **外部上下文：** 授权日历时 `buildExternalContext` 继续输出「日历今日：…」行（已有 `integrations/context.js`）。

### 4.4 栖店（D6）— 新建 `[data-phone-screen="shop"]`

**全新 App，验收硬门槛：**

1. Home → 新图标 **栖店**（建议 `icon: "store"` 或 `"shopping-bag"`，`tone: "coral"`，`page: 2`，`job: "礼物与日常"`）。
2. **商品列表：** 2 列 **商品卡** — 上方 cover（`coverTone` 渐变 + emoji 或插画占位，禁止破图）；标题 2 行 ellipsis；价格 **xx.xx 栖币**（与 F1 钱包同币种，禁止 ¥ / 法币文案）；主按钮「购买」；分类 tab 可选（MVP：`礼物` / `日常` / `限定` 三组 seed）。
3. **下单确认 sheet：** 商品缩略 + 数量（默认 1）+ 应付栖币 + 当前余额；余额不足 → 按钮 disabled + 文案「余额不足，去 Pop 收信物吧」；确认 → loading → 成功态。
4. **订单列表页：** 行 = 缩略图 + 商品名 + 金额 + 状态 pill（已付款 / 待发货 / 已完成）；点进 **订单详情**：
   - 订单号（`orderId`，可复制样式 monospace）
   - 商品明细、下单时间、状态时间线（简化 2–3 步即可）
   - **像电商详情卡片**（U10），不是聊天里一句「买了围巾」
5. **钱包：** 下单成功 → `loadWallet` 的 `balance` 减少、`ledger` 追加 `type:"debit"` + `reason:"shop.purchase"` 行；Pop 钱包页（F1）与栖店读到 **同一** `yueqi.wallet.v1`。
6. **侧写 C6：** 同一 `orderId` 可被 F2b 生成/手填进 sidewrite c6 payload（本波仅保证 **格式一致** + 可选导出 helper，不做侧写 UI）。

### 5.3 钱包与 ledger（I3 · **F1-core 已落地，F3 只调用**）

F3 **不重新定义**钱包协议；**禁止**新建 `src/wallet/store.js` 或发明 `debitWallet`。唯一入口：

**`src/wallet/ledger.js`（以源码为准）**

```typescript
/** @typedef {object} WalletState */
{
  balance: number,              // ≥0，两位小数
  currency: "nyra_coin",        // 固定；UI 文案「栖币」
  updatedAt: string,            // ISO8601
  ledger: LedgerEntry[],
}

/** @typedef {object} LedgerEntry */
{
  id: string,                   // `ldg-…`
  type: "credit" | "debit",
  amount: number,               // 正数
  balanceAfter: number,
  reason: string,               // 栖店固定 "shop.purchase"（F1 已预留）
  refMessageId?: string,
  refCharacterId?: string,
  note: string,                 // ≤80，如「栖店 · 夜灯」；可含 orderId 摘要
  createdAt: string,            // ISO8601
}
```

**本波调用：**

- `loadWallet()` / `canAfford(amount)`
- `applyDebit(wallet, { amount, reason: "shop.purchase", note, refCharacterId })` → 若 `result.error === "insufficient_balance"` 则不下单；否则 `saveWallet(result)` 并读 `result.ledger.at(-1).id`
- 便捷：`debit("shop.purchase", amount)` → `{ ok, error?, ledgerId?, balance }`（内部已 save）
- **订单关联：** `note` 含商品名；`orderId` 写入订单表；可选在 `placeOrder` 成功后 `appendCohabitEvent({ meta: { orderId, ledgerId } })`

**键：** `yueqi.wallet.v1`（`LOCAL_KEYS.walletKey`）

**初始余额：** F1 默认 `200` 栖币；手测勿再假定「手动 fixture 才有钱」。

### 5.4 栖店订单 `ShopOrder`（D6）— **与 F2b C6 对齐（硬约束）**

**orderId 格式（全局唯一，F2/F3 共用）：**

```text
ord-{base36timestamp}-{8位小写hex}
例：ord-m2k3f1a-7c4e9b2d
```

生成：`orderId = \`ord-${Date.now().toString(36)}-${Math.random().toString(16).slice(2, 10)}\``

```typescript
/** @typedef {object} ShopOrder */
{
  orderId: string,           // 格式见上；C6 必填
  amount: number,            // 正数，订单总额；栖币
  currency: "nyra_coin",     // 与 F1 钱包一致；**取代** F2 草稿里的 "CNY"
  shopName: "栖店",          // 固定中文；C6 必填
  status: "paid" | "pending" | "shipped" | "done",
  items: ShopOrderItem[],
  createdAt: string,         // ISO8601
  updatedAt: string,
  characterId?: string,      // 送给谁；可选
  ledgerId?: string,         // 扣款成功后回填 F1 ledger 行 id
  note?: string,
}

/** @typedef {object} ShopOrderItem */
{
  productId: string,
  title: string,
  qty: number,
  unitPrice: number,
  coverTone: string,         // phone-shell tone
  coverEmoji?: string,
}
```

### 9.1 本波功能手测（路径级，必须逐步照做）

#### 前置

1. 本地 `npm install`；浏览器打开栖机（小手机模式）。
2. 确认 **生活库** 有 seed 曲目 / 书籍（默认 `defaultLibrary` 即有）。
3. 钱包：F1 默认初始 **200 栖币**；可用 `resetWalletFixture({ balance: 100 })` 调余额。
4. 设置 → **主动消息** 开；通知授权开；日历授权开。

#### D3 一起听

1. Home → **一起听** → 期望 **300ms 内** stage + 曲目列表可见（E9）。
2. 点列表第二首 → 期望切歌、**播放钮变暂停**、进度条走动；stage 曲名更新。
3. 拖进度条 → 期望 `currentTime` 跟随；松手后仍播放。
4. 关 **共听** Switch → 回 Pop 发消息 → 期望回复 **不** 强调当前在听（或 external 块无共听行）。
5. 开共听 → 暂停 → 期望 Pop 线程可选出现系统条「共听已暂停…」（与 App 版一致即可）。
6. **刷新页面** → 再进一起听 → 期望 **同一首 + 进度约等于** 刷新前（±2s）。
7. 控制台无 red error；Network 面板 **无** 第三方音乐 API 请求。

#### D4 一起看

1. Home → **一起看** → 书架 ≥1 本；封面显示进度标签。
2. 点《挪威的森林》→ 进入 **阅读器**（非空壳）；可滚动正文。
3. 滚到 ~40% → 返回书架 → 再进 → 期望 **滚动位置恢复**；进度标签含 `%` 或章节。
4. 点 **继续共读**（或等价）→ Pop 出现预填消息含书名 / excerpt。
5. 刷新 → 进度仍在。

#### D5 日历

1. Home → **日历** → 月历有 `has-event` 点（seed 事件）。
2. 选明天 → 添加 → 选 chip **共读** → 保存 → 日 sheet 见新事件。
3. Dev：把系统时间调到事件前 1 分钟（或项目内 test hook 触发 scheduler）→ 期望 Pop **栖息 / 主动消息** 一条，文案与 prompt 相关。
4. 删除事件 → 期望不再触发；**reschedule** 后无 duplicate 轰炸（P3）。

#### D6 栖店

1. Home → **栖店** 图标存在且 label 为「栖店」。
2. 商品列表：**卡片** 含图/占位 + 栖币价 + 购买钮（U10）；无 ¥ / 法币。
3. 点购买 → 确认 sheet → 确认 → 期望 success；**余额减少**；ledger 多一行 `type:"debit"` + `reason:"shop.purchase"`。
4. 进 **订单** tab / 列表 → 点刚订单 → **详情页** 见 `orderId`、商品、金额、状态；**不是**纯文本气泡。
5. 复制 `orderId` → 对照 `shopOrderToSidewriteC6Row` 输出字段与 §5.4 C6 表一致（人工或 console 调函数）。
6. 余额设为 0 → 再购买 → 期望 **disabled + 余额不足文案**，ledger **不变**。

#### 反向 / 失败

- 曲目无 `mediaId`：可展示 metadata，播放钮 disabled + 说明，不 throw。
- 钱包未初始化：`loadWallet()` 自动 init 200，不 crash。
- 关主动消息：日历到点 **不发** Pop（或仅系统静默，按产品设计二选一，须在代码 comment 写清）。
