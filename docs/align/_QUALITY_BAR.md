# 月栖 · 栖机质量门槛（所有 Fn 强制）

> 本文件是 [LIVING_PHONE_PLAN](../LIVING_PHONE_PLAN.md) 与各 [align/Fn.md](./F0.md) 的**共用验收上限**。  
> 「功能做出来」不等于过关：UI 与工程必须达到下方门槛，否则该波视为未完成。  
> 对标的是**业界拟真小手机的完成度预期**（真机感、App 内闭环、数据可备份、弱网/坏数据不崩），用月栖自己的标准表述，不引用外部产品名。

详细化任一 Fn 时，必须把本文件的「通用门槛」**逐条拷进该 Fn 的 §9**，再追加本波专属条款。执行 Fn 时，通用门槛与专属条款**全部打勾**才算落地。

---

## 1. UI / 交互门槛（视觉与手感）

### 1.1 第一眼

| # | 门槛 | 不通过的例子 |
|---|------|----------------|
| U1 | 栖机首屏是**一部手机**：状态栏 + 壁纸大气氛 + 图标网格 + Dock，不是网页仪表盘 | 白底表单墙、大片空白无层次、图标像后台菜单 |
| U2 | 品牌可读：打开栖机仍能感到是**月栖**（字体/色板/气质与现有壳一致），不是另一套默认 UI | 突然换成 Inter/系统默认紫渐变/与 `phone-shell.css` 割裂 |
| U3 | **一个 App 一个主色调与信息架构**；列表/详情/编辑层级清晰 | 同一屏塞设置+feed+作曲家三套控件 |
| U4 | 有真实视觉锚点（壁纸、角色头像、内容缩略图），不靠纯色块冒充「做完了」 | 全是灰框 placeholder 仍标已完成 |

### 1.2 动效与反馈

| # | 门槛 | 不通过的例子 |
|---|------|----------------|
| U5 | 关键/返回/切 Tab **至少**有 150–280ms 过渡；尊重 `prefers-reduced-motion` | 硬切无过渡；或满屏闪烁粒子 |
| U6 | 主按钮有 pressed / disabled / loading 三态；异步操作有进行中反馈 | 点了没反应直到突然跳页 |
| U7 | 空态 / 错态 / 离线 **有文案 + 可行动作**（重试、去设置、去选角色） | 空白屏、`undefined`、裸 `Error:` |
| U8 | 触控目标 ≥ 44×44 CSS px（图标按钮含热区）；列表行可扫可读 | 只有 16px 图标才能点 |

### 1.3 拟真完成度（相对「能点开的壳」）

| # | 门槛 | 不通过的例子 |
|---|------|----------------|
| U9 | 每个交付 App：**列表 → 详情 → 返回** 完整；返回不丢滚动位置（或明确重置） | 只能进不能回；返回整页重载丢位置 |
| U10 | 结构化内容（信物卡片、侧写记录、订单）**像真 App 气泡/行**，不是纯文本拼出来 | 红包显示成 `[redpacket]100` |
| U11 | 桌面图标、App 内标题、文案用语与用语表一致（侧写/动态/栖店…） | 中英混杂临时词、内部 id 露出 |
| U12 | 375×812 与 390×844 视口手测通过；横滑桌面不撑破外框 | 溢出裁切、双滚动条打架 |

**判定：** 本波新增或大改的每个 UI 面，U1–U12 全过；跳过项必须在 Fn §9 写明「为何本波不适用」且不得用于遮羞未做完的主路径。

## 2. 工程 / 代码门槛

### 2.1 结构

| # | 门槛 | 不通过的例子 |
|---|------|----------------|
| E1 | 领域拆分：存储 / 引擎（生成或规则）/ UI 分层；禁止 3k+ 行单文件堆一波功能 | 一个 `xxx-app.js` 含 prompt+DOM+IDB |
| E2 | 持久化有**唯一模块清单**（键名、store 名）；可被备份契约引用 | 魔法字符串散落、刷新丢数据 |
| E3 | LLM 输出有 **schema / 校验 / 降级**；坏 JSON 不白屏 | `JSON.parse` 裸奔导致整页挂 |
| E4 | 场景标签：本波若碰 prompt，必须带正确 `appId`，禁止串戏污染 | 侧写上下文泄漏进日常闲聊无标记 |

### 2.2 可靠与可测

| # | 门槛 | 不通过的例子 |
|---|------|----------------|
| E5 | `scripts/verify-align-fN.mjs` 覆盖：**纯函数 + schema 样例 + 关键键存在性**；挂脚本到 package.json | 只有「我手测过了」 |
| E6 | 无 API key / 离线：主路径可演示或明确降级，**不抛未捕获异常** | 控制台红一片、按钮死锁 |
| E7 | 不引入对照仓代码、不提交密钥；新依赖许可证可开源 | 直接 copy 外部实现文件 |
| E8 | 与现有模块对接点写在 Fn §6；改公共 API 保持向后兼容或写迁移 | 默默改 `assemble.js` 签名弄挂聊天 |

### 2.3 性能体感

| # | 门槛 | 不通过的例子 |
|---|------|----------------|
| E9 | 首开 App：本地数据路径 **&lt; 300ms** 出骨架（无等待 LLM）；需 LLM 的出「生成中」 | 白屏等模型 10s 才出壳 |
| E10 | 列表虚拟或分页：同屏 &gt;100 条不卡死主线程（侧写记录、动态） | 一次 innerHTML 塞 2000 条 |

## 3. 产品语义门槛（「像活人」）

| # | 门槛 | 不通过的例子 |
|---|------|----------------|
| P1 | 用户在本波 App 的操作，若承诺写入同栖时间线，**回 Pop 可被 prompt 读到**（有事件、有标签） | 侧写看完聊天毫无反应 |

## 5. 波次未完成的定义（失败即打回）

出现任一条，**不得**把 Fn 标为「已落地」：

1. 主路径能跑但 UI 仍是灰框/裸列表/无状态栏层级  
2. 有功能无校验：LLM 或用户输入可打崩页面  
3. 无 verify 脚本或脚本不测本波核心协议  
4. 文案或架构泄漏外部产品名 / 对照路径  
5. 「先凑合以后再美化」写进合并说明当作交付
