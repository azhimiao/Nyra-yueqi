## 4. 产品语义（月栖用语，交互长什么样）

### 4.0 创作管线总览（Agent 必须先读懂）

```
资源库 F6 ──► 点「角色卡」──► 角色编辑 / 导入 F1
                │
                ├─► 世界书 F2 ──► 关键词命中 ──► assemble.js worldbook 块
                ├─► 预设 F3 ──► promptSystem / developer 前缀
                ├─► 正则 F4 ──► 入站(用户) / 出站(AI) 管道
                └─► 栖笺 F5 ──► 草稿 ──► upsertCharacter ──► profile.js ──► assemble.js character 块
```

**存储分工：** 角色正文 → IndexedDB `characters` + `profile` 镜像；世界书 → `worldbook` store；预设 / 正则 → 独立 localStorage 键（§5.1）；书籍 / 媒体 → 已有 `library` + `media` store。

### 4.1 F1 · 角色卡导入

**入口（三处，行为一致）：**

1. 设置 → **身份** → 顶栏「导入角色卡」
2. 栖机 App **角色**（`profile`）→ 导入
3. **资源库** → 「角色卡」分区 → 「从文件导入」

**路径：** 选文件 → 全屏轻遮罩「正在解析…」（U6）→ **预览页**：

- 左：解析摘要（姓名、身份、人设摘要前 120 字、tags 数、warnings）
- 右：头像占位（有则缩略图；无则 mint 渐变 + 首字）
- 底栏：**导入为新角色** | **覆盖当前编辑中角色**（二次确认 sheet，禁止 `window.confirm`）| 取消

**成功：** toast「已加入角色库」+ 可选「设为陪伴角色」→ 列表见新卡 → Pop 选 DM 可聊。

**错态（U7）：** 「这张卡缺少可读人设」「JSON 格式无法识别」「ZIP 不是月栖角色包」+「重选文件」；禁止裸 `SyntaxError`。

**与角色包区分：** `.json` / `.png` / `.webp` 走 **F1 卡导入**；`.zip` 且含 `manifest.json` 走 **`character-pack`**（视觉包，已有 `parseCharacterPackZip`），导入成功后进入桌宠 / 外观路径，**不强制**创建新 CharacterRecord（若 pack 含 `persona` 可选合并）。

### 4.2 F2 · 世界书

**入口：** 设置 → **世界书**（已有 `data-settings-view="worldbook"`）；栖机 **资料** 屏（`data-phone-worldbook` mini feed）；资源库 → 世界书分区。

**列表页（设置内）：**

- 顶：说明一句「关键词出现在对话里时，会把对应设定注入 prompt」
- 每行卡片：标题、分类 pill（氛围 / 规则 / 人物）、优先级数字、启用开关；展开见 triggers 标签 chips + 内容 textarea + 「写到」下拉（场景设定 / 人物侧写 / 回复约束 → 映射 `injectSlot`）
- 底：**+ 新条目**；批量「全部禁用」仅调 `enabled:false`，不删

**栖机资料快捷 feed：** 只读最近 3 条命中或置顶；点「编辑全部」跳设置 worldbook 视图。

**匹配语义（与现码一致）：** 用户本轮 `query` 对 `triggers[]` 做 **子串 includes**（大小写敏感按现实现；本波可增「忽略大小写」设置，默认 false 保兼容）；按 `priority` 降序；`enabled:false` 跳过。

**场景标签（F0 对接）：** 条目可选 `scopeApps: string[]`（如 `["pop"]` 仅聊天；`["scenario"]` 仅情景剧；空 = 全局）。`assemblePrompt({ appId })` 过滤后再匹配。

### 4.3 F3 · 预设

**入口：** 设置 → **进阶** → 新增小节「回复预设」；Pop 输入栏上方可选 **预设 chip 条**（展示当前名，点进选择器 sheet）。

**选择器 sheet：** 375 宽 bottom sheet；每项 = 名称 + 一行描述 + 选中勾；底部「管理预设」→ 完整列表。

**管理页：**

- 内置 3 套（不可删，可 Duplicate）：**日常陪伴**、**文艺慢聊**、**克制边界**
- 用户预设：名称、描述、**系统前缀** textarea、**开发者补充** textarea（可选）、**语气 hint**（温柔 / 灵动 / 克制 等多选 chips）
- 切换预设 = 写 `activePresetId`；**不修改**角色卡 `profile.fields`，只改 prompt 层

**可感知差异：** 同一句「今天有点累」——日常 vs 克制边界，系统前缀中边界 / 现实提醒强度不同；debug 面板可见 `promptSystem` 变化。

### 4.4 F4 · 正则

**入口：** 设置 → **进阶** → 「文本变换（正则）」；分 Tab **入站** | **出站**。

**列表行：** 名称、启用开关、顺序号（拖拽或 ↑↓）；展开：模式（字符串）、替换 / 模板、flags（`i` `g`）、**仅匹配一次** 开关。

**内置样例（必须预置且可禁用）：**

| id | 方向 | 名称 | 作用 |
|----|------|------|------|
| `builtin-out-strip-think` | 出站 | 收起思考标签 | 去掉 `…` 块 |
| `builtin-in-trim-spaces` | 入站 | 合并多余空白 | 连续空白 → 单空格 |

**运行位置：**

- **入站**：`panels/chat.js` 发送前 → `applyInboundRegex(userText)`
- **出站**：模型返回后、渲染气泡前 → `applyOutboundRegex(assistantText)`

**失败行为：** 单条规则 compile 失败 → 标记 `broken:true` 并在 UI 显示警告，**跳过该条**；运行时异常 → 返回原文 + `console.warn`（E3）。

### 4.5 F5 · 栖笺

**入口：** 设置 → **身份** 页标题旁 **「栖笺」** 按钮；资源库 → 选一张卡 → 「用栖笺润色」。

**起草屏（独立 subview 或 modal，禁止与身份表单混成一屏无标题）：**

1. **种子区**：关系（下拉：朋友 / 恋人 / 家人 / 自定义）、关键词（3–8 个 chips）、语气（复用预设 hint 或自由一句）、可选「参考世界书条目」（多选 chips，读 `worldbook` id 列表）
2. **生成**：主按钮「生成草稿」→ loading 骨架（U6）；无 key 走 **离线模板**（§5.6）
3. **结果区**：分块展示 — 姓名建议、关系称呼、身份、**人设摘要**（`fields[4]`）、偏好词 `tokens`；每块可单独编辑
4. **对比条**：折叠「与当前对比」→ 左右 diff（旧灰 / 新高亮）
5. **底栏**：**采用**（调 `syncProfileStateToCharacter` / `upsertCharacter`）| **丢弃** | **再生成**

**LLM 通道：** `appId: "qijian"`；输出 JSON schema §5.6；解析失败 → 离线模板，不白屏。

### 5.2 F1 · 开放 JSON 角色卡（导入解析目标）

解析器输入：UTF-8 `.json` 文件，或 PNG/WebP 内嵌 JSON（读取 APP1 tEXt / 自定义 chunk / 同名 `.json` 侧车）。

**逻辑形状（兼容常见开放格式，字段名映射）：**

```ts
/** 解析中间态 */
type ParsedCharacterCard = {
  name: string
  alias?: string
  identity?: string
  description: string          // → profile.fields[4]
  personality?: string         // 合并进 description
  scenario?: string            // → 可选追加世界书草稿（不自动保存，预览提示）
  firstMessage?: string        // → 可选写入 greeting 提示（本波可仅存 import meta）
  tags?: string[]              // → profile.tokens
  avatar?: string              // data URL 或 http(s) — 仅 https/data 允许
  extensions?: Record<string, unknown>  // 忽略未知键，不报错
  rawVersion?: "v2" | "v3" | "unknown"  // 内部诊断，UI 不展示品牌
}
```

**映射到 `CharacterRecord`（`normalizeCharacter`）：**

| 源字段 | 目标 |
|--------|------|
| `name` | `name`, `profile.fields[0]` |
| `alias` / 缺省用 name | `alias`, `profile.fields[1]` |
| `identity` / 缺省「未设定身份」 | `profile.fields[2]` |
| `description` + `personality` | `profile.fields[4]` |
| `tags` | `profile.tokens` |
| — | `profile.fields[3]` 保留用户当前或默认模型名 |
| — | `source: "import"`, `loreEntryIds: []` |

**校验 / 降级：**

- `validateParsedCard(card): { ok, errors[], warnings[] }`
- 缺 `name` → 用文件名 stem；缺 `description` → `warnings` + 占位「待补充人设」
- 头像 URL 非 https/data → 丢弃 avatar 并 warning

**纯函数（须单测）：** `parseJsonCharacterCard(text)`, `extractJsonFromImage(bytes)`, `mapParsedCardToCharacter(parsed, { id? })`

### 5.3 F2 · 世界书条目 `WorldbookEntry`（扩展）

```ts
{
  id: string
  title: string
  category: "氛围" | "规则" | "人物" | string
  triggers: string[]              // 至少 1 个；保存时 trim、去空
  content: string
  injectSlot: "world_context" | "character_context" | "reply_policy" | "system"  // 默认 world_context
  priority: number                // 0–100，默认 50
  enabled: boolean
  scopeApps?: string[]            // 本波新增；空/缺 = 全局
  linkedCharacterIds?: string[]     // 可选：仅这些角色会话生效
  updatedAt?: string              // ISO
}
```

**匹配纯函数：**

```ts
matchWorldbookEntries(entries, query, { appId?: string, characterId?: string }): WorldbookEntry[]
```

规则：`enabled` → `scopeApps` → `linkedCharacterIds` → trigger includes → sort by priority desc。

**对接 `assemble.js`：** 将现内联 filter 抽至 `src/worldbook/match.js`；`assemblePrompt` 增参 `appId`（默认 `"pop"`），替换 287–292 行逻辑。

### 5.4 F3 · 回复预设 `ReplyPreset`

```ts
{
  id: string
  name: string
  description: string
  builtin: boolean                // true = 不可删
  promptSystemPrefix: string      //  prepend 到 compiled.promptSystem 前（空行分隔）
  promptDeveloperAppend: string   // append 到 promptDeveloper
  toneHints: string[]             // UI 用；可选注入 character 块一句
  createdAt: string
  updatedAt: string
}
```

**Bag 形状（`yueqi.presets.v1`）：**

```ts
{
  activePresetId: string
  presets: ReplyPreset[]
}
```

**内置 id：** `preset-daily` · `preset-literary` · `preset-boundary`

**合并规则（纯函数 `applyPresetToPromptTexts(base, preset)`）：**

- `promptSystem = [preset.promptSystemPrefix, base.promptSystem].filter(Boolean).join("\n\n")`
- `promptDeveloper = [base.promptDeveloper, preset.promptDeveloperAppend].filter(Boolean).join("\n\n")`

在 `collectPromptTexts()` 或 `assemblePrompt` 入口调用；**角色卡内** `profile.promptSystem` 仍为 base。

### 5.5 F4 · 正则规则 `RegexRule`

```ts
{
  id: string
  name: string
  direction: "inbound" | "outbound"
  pattern: string                 // JS RegExp source；禁止 lookbehind 若目标环境不支持则 verify 注明
  replacement: string             // 支持 $1 捕获组
  flags: string                   // 默认 "g"；入站样例 "g"，出站 "gis"
  enabled: boolean
  order: number                   // 越小越先执行
  builtin?: boolean
}
```

**管道纯函数：**

```ts
compileRegexRule(rule): { ok: true, re: RegExp } | { ok: false, error: string }
applyRegexPipeline(text, rules): { text: string, applied: string[], skipped: string[] }
```

坏规则跳过；整体 never throw 到 chat 层。
