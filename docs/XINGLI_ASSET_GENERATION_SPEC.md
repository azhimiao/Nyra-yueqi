# 星梨动态桌宠资产生产规范

> 适用范围：内置角色「林星梨 / 星梨」及后续同规格角色包。
>
> 目标：用**角色锁图 + 少量可控关键姿势**生产可商用、可替换、可验收的桌宠素材；运行时以序列帧图集播放，并由 `emotion`、`action_id` 与用户手动选择共同驱动。

## 1. 不可变原则

1. 星梨是 **22 岁成年女性**。可爱、半 Q，不等于儿童体型；镜头中必须能读出成年肩颈、腰线、手脚和腿部比例。
2. 每一批动作必须上传同一张已人工确认的 `character_lock.png` 作为角色参考。不能只靠文字重新生成“相似角色”。
3. 每个动作输出完整全身、透明 PNG、固定镜头与一致的角色锚点；站姿的鞋底必须在同一基线。
4. 动作是表现层资产，不让模型直接控制播放细节。模型只能提出有限的 `emotion` / `action_id`；本地播放器按 manifest 播放、转场、回退。
5. 用户上传的角色包与内置星梨包分开保存。内置技术 ID 可以保持 `xingli` / 历史兼容 ID，不以显示名称变更数据结构。

## 2. 目录与交付物

每一个待导入角色包应采用下列结构。生成过程中的草稿、联系表不得被运行时当作帧加载。

```text
character-package/
├── character/
│   ├── candidate_a.png
│   ├── candidate_b.png
│   ├── candidate_c.png
│   └── character_lock.png          # 人工冻结的唯一人物参考
├── clips/
│   ├── idle_loop/idle_000.png
│   ├── talk_loop/talk_000.png
│   └── ...
├── expressions/                    # 可选：完整全身表情参考
├── face/                           # 可选：眼、嘴差分来源，不直接替代全身帧
├── previews/                       # 联系表，仅供人工验收
├── asset_manifest.json             # 原始生产清单
└── generation_report.md            # 生成与人工验收记录
```

运行时导入后产物为：

```text
public/assets/characters/xingli/
├── manifest.json
├── portrait.png
└── clips/
    ├── idle_loop.png
    ├── idle_loop.json
    └── ...
```

## 3. 端到端执行流程

### 3.1 角色锁图候选

1. 一次生成 3 张**完整全身**候选图，统一使用第 4 节的角色锁定提示词。
2. 候选图必须是独立 PNG，不使用九宫格、转向拼贴或带文字的展示页作为运行时源图。
3. 人工从候选中选择一张，并检查：成年感、五官、发型、服装、色彩、鞋底、手部、透明边缘。
4. 把选中的图命名为 `character/character_lock.png`。冻结后，任何后续动作只能引用它；需要改发色、服装或年龄感时，创建新的角色包版本，不在同一包中混用。

### 3.2 人工选定与锁定记录

在 `generation_report.md` 记录：

- 角色包 ID、显示名、版本、锁图文件名、生成日期。
- 人工确认人、确认日期、是否为成年角色。
- 不可变外观：发色、瞳色、发型、服装、袜鞋、比例、鞋底锚点。
- 不接受项：任何校服元素、儿童化比例、换装、脸型漂移、背景或水印。

冻结时建议保存一张 100% 放大的面部检查图和一张完整全身检查图。它们是后续返工的判定依据。

### 3.3 使用同一参考生成动作关键姿势

1. 每次生成动作都上传 `character_lock.png`，并附上第 4 节的固定前缀、第 5 节对应动作后缀与第 6 节负面约束。
2. 优先生成**关键姿势序列**：开始、过渡、主要姿势、回位；不要请求一整张拼贴表情页。
3. 循环动作至少需要能辨认的呼吸、眨眼、头部或衣发微动；首尾姿势必须可循环。
4. 一次性动作必须有可识别的开始、中段和结束，最后帧应能自然回到 `idle_loop`，或明确进入 `sit_idle` / `sleep_loop`。
5. 大姿态变换拆为独立 clip：`stand_to_sit -> sit_idle`，`sit_to_sleep -> sleep_loop`。不要由运行时硬切换站姿和睡姿。
6. 每次只生成一个动作，先过人工 QA 再继续下一个。出现脸、服装、构图漂移时，废弃整批并从锁图重新生成。

### 3.4 洋红去色键与透明化

优先要求生成透明 PNG。若生成工具无法稳定输出透明通道，可采用**仅用于临时生产的纯洋红背景**：`#FF00FF`。

1. 背景必须是单一、完全不透明的 `#FF00FF`，不允许渐变、光斑、阴影、地面或同色衣物。
2. 人物线稿、头发边缘和衣物不得使用接近 `#FF00FF` 的紫红色高光，以免去色键时被误删。
3. 去色键脚本只删除与 `#FF00FF` 足够接近且**与画布边缘连通**的像素；不应删除角色内部孔洞、眼睛或衣物细节。
4. 去色键后逐帧检查发丝、手指、裙边和鞋底是否出现洋红边或透明破洞。失败帧需要重新生成或人工修复。
5. 透明化完成后，最终源图必须为 RGBA PNG；洋红底图不进入 `public/assets`。

### 3.5 源资产 QA

每个 clip 在导入前完成以下验收：

| 检查项 | 通过标准 |
| --- | --- |
| 画布 | 所有源帧同尺寸，推荐 1536x1536 RGBA PNG |
| 全身 | 头顶、双手、裙摆、双脚不裁切；没有额外人物或道具漂移 |
| 一致性 | 脸型、绿发、金瞳、白裙、粉色腰带、白袜、棕鞋没有变体 |
| 锚点 | 站立帧鞋底基线一致；坐卧帧的画面中心和安全留白一致 |
| 动作 | 相邻帧至少存在合理、连续的关节或衣发变化；不是重复静态图堆叠 |
| 透明 | 四角透明；无洋红边、无白底、无地面阴影、无水印 |
| 循环 | loop clip 首尾可衔接；once clip 结束姿势可回退 |
| 手部 | 手指数量和手势稳定；无额外手、断手、穿模 |

将每个动作的联系表保存在 `previews/`，并在报告中记录“通过 / 退回 / 重做”的原因。

### 3.6 导入、图集与 manifest

导入程序应承担机械工作，而不重新解释角色语义：

1. 验证路径安全、PNG 格式、画布尺寸、Alpha 通道与帧排序。
2. 裁去透明留白并保持每帧在固定逻辑画布中的锚点。
3. 将每个 clip 打包为一张 atlas PNG 和对应 JSON 索引，保持原始帧顺序。
4. 生成 `manifest.json`：clip ID、帧数、fps、循环方式、crossfade、returnClip。
5. 不把 `previews/`、候选图、脸部拼贴、生成报告或带底图草稿导入运行时。

建议命令占位如下。实际脚本名以仓库现状为准：

```powershell
# 只从已验收的原始角色包导入，不在命令行填写任何密钥
node scripts/import-xingli-pack.mjs <已验收角色包目录> public/assets/characters/xingli

# 校验导入结果与 manifest
node scripts/verify-sprite-character.mjs
```

### 3.7 运行时 QA

导入成功不代表桌宠体验合格。必须在真实浏览器和 Windows 透明置顶窗各验收一次：

1. `idle_loop`、`talk_loop`、`listen`、`thinking`、`sit_idle`、`sleep_loop` 连续播放不闪白、不空白、不越界。
2. 状态切换有短交叉淡化；不会因同一状态重复写入而不断从第 0 帧重播。
3. `stand_to_sit` 播放后进入 `sit_idle`；`sit_to_sleep` 播放后进入 `sleep_loop`；一次性动作回到 `idle_loop`。
4. LLM 只能从允许的回复动作集合中选择；`drag`、坐下和入睡等只允许手动、系统或场景触发。
5. 手动动作面板能播放全部可见动作；“自动跟随回复”恢复后，运行时状态重新接管。
6. 在窄小悬浮窗、普通 App 模式与小手机模式中均不裁切、文字不遮挡角色、Canvas 像素非空。

## 4. 星梨角色锁定提示词

将以下内容作为所有星梨资产生成的固定前缀。将 `character_lock.png` 同时作为人物参考图上传。

```text

```

## 6. 统一负面约束

每次动作生成都附上以下文本：

```text

```

对于连续帧，再追加：

```text
生成连续动画关键帧，不是多张相同站立图；每帧人物大小、镜头距离、角色中心、鞋底基线、服装和五官必须一致。相邻帧只改变动作所需的关节、表情、头发和裙摆惯性。每个循环动作首帧与末帧姿势一致；每个一次性动作必须有开始、中间、结束三个可辨识阶段。
```

## 7. 为什么不使用 116 张独立 AI 重绘帧

“116 张图”不是“116 个连续动作”。如果对每帧都单独请求 AI 重绘，通常会产生：

- 五官、瞳色、发丝、服装褶皱和肢体比例逐帧漂移；
- 镜头缩放、人物中心与鞋底锚点变化，桌宠看起来跳动；
- 手指、裙摆、道具在中间帧突然重画或消失；
- 帧数很多但独特姿势很少，播放仍像切换静态图片；
- 返工成本随帧数线性增长，且很难定位哪一帧破坏了角色锁定。

因此采用“锁图 -> 单动作连续关键姿势 -> 人工 QA -> 图集”流程。循环只需少量高质量帧；一次性动作只需足够描述起止和惯性的帧。运行时用固定 fps、短 crossfade、回退 clip 和状态机把它们连贯起来。若需要真正逐帧高流畅度，应使用同一生成任务的受控视频/序列能力，或由动画师在锁定原画上补间，而不是重复独立文生图。

## 8. 模型与密钥安全

### 8.1 密钥规则

- API Key 只从环境变量读取；不得写入 Markdown、源码、manifest、截图、日志、命令历史或仓库配置。
- 不提交 `.env`、生成服务返回的请求头、完整 URL 查询参数或任何真实密钥。
- 示例命令只写变量名与占位值，绝不粘贴真实 token。

### 8.2 模型环境覆盖

不同生成环境可自行覆盖模型名与端点。生产脚本应优先读取环境变量，未设置时使用本地安全默认值或明确报错，不应把供应商和密钥硬编码到角色包中。

```powershell
# 当前 PowerShell 会话的示例；值均为占位符
$env:ARK_BASE_URL = "https://ark.cn-beijing.volces.com"
$env:ARK_API_KEY = "<set-in-local-shell-only>"
$env:ARK_IMAGE_MODEL = "doubao-seedream-5-0-pro-260628"

# 先生成三张锁图并人工验收，再以选中的候选生成24张关键姿势
npm run generate:xingli -- --stage lock
npm run generate:xingli -- --stage poses --select 1
npm run verify:xingli-source
npm run import:xingli
npm run verify:xingli
```

如果没有受控生成脚本，则在生成工具 UI 中手动上传锁图，复制第 4、5、6 节文本；下载结果后再进入本规范的去色键与 QA 阶段。无论采用何种工具，密钥不属于角色包、仓库或交付物。

## 9. 发布前最小验收清单

- [ ] `character_lock.png` 已人工签收，外观与成年设定一致。
- [ ] 16 个 clip 都有语义、来源帧、循环/回退定义和联系表。
- [ ] 无洋红底、白底、水印、背景、裁切或明显漂移帧。
- [ ] 导入器与 sprite 校验命令通过。
- [ ] App 模式、小手机模式、Windows 悬浮窗中均能正常播放。
- [ ] 回复状态、语音监听、点击、拖动、手动动作和睡眠状态映射正确。
- [ ] 生成与运行日志不包含 API Key、Authorization 头或真实端点机密。
